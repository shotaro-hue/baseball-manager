# 複数故障後の緊急守備補充

基準main: `7ec61c5e0634319f0a577eb6744e8224ea77ca0d`（PR #441反映）。

## 原因

初期生成seed 1、自球団4、遊撃手を10日故障、試合進行seed 99で5試合進めると、兼任遊撃手も故障し打順が7人になる。二軍には健康な遊撃手が残るが、短期故障の緊急処理は一軍の控えだけで補充していた。故障者が打順から外れた後は、次の処理で修復対象にもならない。

## 修正契約

- 手動モードは変更しない。通常の短期故障では一軍登録を維持し、控え・副守備で補充する。
- 一軍だけでDHあり／なしの編成が完成しない場合に限り、実在する二軍選手を必要な人数だけ昇格する。
- 登録上限時は、修復後の両打順に必要な健康な選手・投手・健康な捕手を残し、故障者を優先して入れ替える。既存の昇降格処理で10日の登録待機を付ける。
- 故障・育成・登録待機・外国人登録枠を既存の共通判定で検証する。適性・能力・選手・成績を捏造しない。
- 健康な先発の打順と既存の投手修復を維持する。保存形式・二軍表彰・捕手配分・CPU補強AIは変更しない。
- 登録可能な選手で実際に守備枠を増やせない場合は、既存の編成検証エラーを維持する。

## 検証

- 最小再現の新規3件は修正前に打順不足でRED、修正後GREEN。
- 複数短期故障、登録上限、旧保存の欠けた打順、二重処理、登録待機・故障・育成・外国人枠、総人数・入力不変、不要な昇格なしを単体テストで確認。
- seed 99の実シミュレーションで追加故障・編成妥当性・次戦進行を確認。

- CIの対象コミットでビルド・全体テスト・両ブラウザ等の全6ジョブを別途確認する。実端末・長期全シーズン保証ではない。
