## 変更と制度上の判断

#512では補償が未実装のため、A/B FAの他球団移籍を一律に受諾拒否していた。今回は原提示に旧年俸と初回/反復の根拠を保存し、最大金銭補償を留保した受諾を許可する。受諾だけでは旧球団に収入を作らず、旧球団が後から金銭のみを選択する。

- 国内FAと海外FAのNPB内移籍は同じ補償基盤を使う。海外FA資格だけでは国内移籍の補償を免除しない。自由契約、C/exempt、元球団残留には金銭補償を課さない。
- 選手会公開の2009年FA規約第10条とパ・リーグ公式運営の2026年更新解説で、旧球団の選択権、初回A80/B60%、反復A40/B30%、直前シーズン年俸を基礎とすることを照合。2009規約を現行最新版とは扱わない。一次資料へのリンクと留保は設計書に記録する。
- 万円未満切上げ、オフ翌年の契約初年度への一回計上、受取による同年度余力の増加はゲーム側の会計方針。現実の支払日・端数規則の再現ではない。新しい回答乱数、CPU評価、資格式や宣言制度は変更しない。

## 実装経路

- `faCompensation.js`：厳格な補償根拠、BigIntによる率/切上げ、提示IDから決まる支払/受取行、受諾済み原提示との照合。現在の年俸や後日の所属から過去の補償額を作り直さない。
- `acquisitionMarket.js`：A/B FAだけに任意の`compensationBasis`を保全。未記録の旧入力から値を推定しない。
- `annualSpending.js`：提示の初年度留保、受諾後のpending債務、`settleFaCashCompensation`の両側精算。双方の年度許可を要求し、留保と支払を同じ債務として扱う。受取球団が赤字でも収入は受け取れるが、別支出の審査は回避しない。
- `annualAcquisitions.js`：旧球団の`settle-fa-compensation`と時期の検査、精算前の春加入/年度飛越しの拒否。翌春加入は既存の一回処理を使う。
- `annualTransactions.js`：厳格な選択入力、取引ID再適用、保存された精算取引と補償記録の照合。元の明示オファー取引とも条件を照合し、受諾履歴と加入待ち情報を同時に書き換えて補償額を変えることを拒否する。選択日時・金額を入力で偽装できない。

受諾→精算は同日でもよい。JSON後に精算済みをpendingへ戻したり、費目を替えて支払を消したりする状態は拒否する。加入後のトレード、翌年度の給与や契約年数は補償履歴を書き換えない。基盤全体の外部認証を新設したものではなく、信頼する暦・phaseは呼出側が供給する。

検証した主な境界：

- A/Bの初回/反復、旧年俸と新提示額の分離、端数と最大安全整数、補償初年度だけの負担。
- 受諾前の収入なし、受諾後の債務維持、双方の許可額、予算縮小後の精算、赤字受取、別件支出の審査、取消/拒否/競合敗北による留保解放。
- 旧球団以外・未対応方式・日付/金額上書き・未受諾・重複選択を拒否。提示後の旧年俸/反復/ランク/所属/引退変更を再検査。

- 補償記録の欠損/重複、片側/両側費用の欠損、金額/相手/年度/提示ID/費目改変、架空の収入、精算の巻戻しを拒否。

## 本番接続と次工程

**本番未接続。** 新しい補償状態・明示根拠は実ゲームのhook、CPU、委任、Workerや旧セーブへ自動追加しない。JSON回帰は新基盤stateを対象とし、本番の新制度保存移行・年度更新が完了したことを意味しない。ビルド同一性も実iPhone性能検証ではない。旧の市場所属・外国人生成/春更新・年俸控除・更改・新人加入の経路は維持する。

次は人的補償/保護名簿/将来契約移管/枠の設計を独立PRへ分割する。FA獲得人数上限、期限（規約の公示後40日等と延長、ゲーム暦への適用）、海外離脱、145日換算と権利再取得、公示カレンダーの一次資料照合も後続。pendingを自動的に金銭選択済みとは扱わず、期限未定義でも勝手な精算・加入・失効はしない。

その後に年度更新adapter、未回答締め、保存移行、本番の人/CPU/Worker/UIを接続する。動的校正・実iPhone確認・完全バックアップ/復元は未実施。金銭経路だけでFA制度の完成や本番有効化とは扱わない。マージ・auto-merge・main直接pushは行わない。
