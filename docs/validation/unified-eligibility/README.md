# ポスティング・FA資格統合の検証記録

## 基準と範囲

開始時mainは `9ea1468f1f45e5dda97c7db16e16d5d1bb00715e`。#546/#547はマージ済み、#548は未マージ（HEAD `7758f6d87ce5c7edb8d8d36cd233ba3969697bff`）。そのHEADから専用ブランチを作り、既存PRの変更・置換・マージをしない。提出PRのbaseはmain。#548との差分を今回のレビュー範囲とする。

## 計算と保存

- `professionalYears = max(0, completedSeasonYear - proStartYear + 1)`。終了済み年を明示し、当年の未終了季を先取りしない。25歳以上かつ6年以上が制限免除、それ以外は制限あり。移籍、育成/二軍/一軍、無所属期間、出場数で開始年を変えない。
- 実在の未確認開始年は、公式draftYear翌季（956人）または入団履歴/年齢（100人）による明示推定。最古の成績年をプロ入り年とはしない。個別確認した3人を優先。架空新人は最初のプロ契約成立年（signedSeason）に固定し、翌年の効力開始と区別する。既存生成選手は初期化時に一度確定。出生不足は初期化年の3月27日時点でゲーム年齢に合う日付を固定する。追加RNGなし。
- FA国内は高卒等1,160日、2007年以降ドラフトの大卒/社会人1,015日、海外1,305日。未確認入団区分は年齢から学歴を作らず「その他」8年の明示設定。大卒等のdraftYear不足は固定開始年-1をゲーム推定し、2007年前後の閾値を確定する。
- FAは残高と公式保有権を別保存。公式取得済み権は推定残高不足でも維持し、公式資格から正確な累積日数を作らない。NPB再契約で権利を消費し、その後580日で海外FAを再取得する。市場中は宣言時資格を保持し、残留でも加入時に消費する。戦力外の再契約はFA行使に数えない。
- 日次加算は `floor(d*145/143)-floor((d-1)*145/143)`。143日通算145。登録中のみ加算し、二軍/抹消/育成には加算しない。怪我でも一軍登録を保つ間は加算。年別の処理済み日を選手に保持し、移籍・再登録・重複処理で二重加算しない。145日上限、部分年の残高は翌年へ持ち越す。
- 旧`daysOnActiveRoster`・`serviceYears`・`entryAge`は保持。旧残高は145/120倍のゲーム換算として別領域へ移行。真の0と未記録0を区別し、初期未確認フラグが残っていても正の進行カウンターはゲーム履歴として扱う。既に旧規則で保有した権利は保護する。
- 旧セーブの確定FA宣言＋加入済み契約から消費済み起点を復元し、行使後に加わった日数だけを再取得へ算入。未受諾の旧資格証明と、加入待ちの旧snapshotは変更しない。加入待ちsnapshotは加入時に一時コピーへ履歴を投影して次の行使を確定する。旧legacyの球団FA退団履歴も利用する。
- 旧セーブの当年経過ゲーム日を処理済みにする。旧年の登録内訳は復元不能なので、残りの当年加算枠は経過日換算を用いる保守的な移行。既存120換算で過去に生じた年別の過算入まで遡って訂正しない。
- 初期マスタ更新は新規ゲームのみ。旧保存の移行はオンライン/最新マスタを見ない。過去の選手snapshot、署名、receipt、契約台帳、予算、saveId/epoch/revision/randomRootを変更しない。v1資格は当時の式で復元・replayし、新規posting記録はv2かつ現在の固定事実/終了季と完全一致が必要。

## 出典と取得制限

- [2025有資格者](https://npb.jp/announcement/2025/fa_qualified.html)（2025-10-22）、[2025行使/契約](https://npb.jp/announcement/2025/fa_filed.html)（2026-01-26まで）、[2024行使/契約](https://npb.jp/announcement/2024/fa_filed.html)。対象時点/確認日/根拠区分を区別する。原ページ全文や記事・画像を同梱しない。2026シーズン後の資格公示は取り込まない。
- [NPB FA制度](https://www.npb.or.jp/announcement/2019/fa_about.html)、[選手会制度説明](https://jpbpa.net/transfer/)で145日、7/8/9年、行使後4年、傷病特例等を監査。
- [FAカウンター規約](https://www.facounter.net/privacy.html)は自動収集・収集データ再配布を禁止。[NPBase規約](https://npbase.jp/terms)も継続再配布等に制限。非公式日数は0件取込。
- 公式プロフィール約1,000件の一括取得も利用条件未確認として自動承認レビューに拒否されたため実行せず、既存公式事実・少数の個別確認・ゲーム推定を使用した。迂回取得なし。追加収集は権利/取得条件の確認を要する。

## RED→GREENと独立レビュー

開始時3ファイル80件成功。共通モジュール不足、旧日数/不明資格、出生/終了季境界、143日換算、旧保有権、公式権と日数分離、架空初契約、旧実保存等の失敗を先に確認して実装した。

レビューで再現して修正した事項:

1. 戦力外後の再契約で古いFA文言から二重行使と誤認。
2. 公式名簿の否定情報でローカル実測日数を切り下げる誤適用。
3. exerciseBasis欠損が「完全な初回履歴」と解釈される検証不足。
4. 新規v1/不明snapshotの発行と、固定出生/開始年と矛盾するv2発行。
5. 旧#548の既加入・市場中・加入待ちFA保存から再取得周期を復元する不足。
6. 個別入団区分の根拠URLとFA公示URLの混同。
7. 旧カウンターが明示0のときにserviceYearsから「旧取得済み」を作る誤認。推定残高と旧権利保護の基準を分け、追加RED→GREEN・関連5ファイル74件・独立確認を実施。
8. 未来年度の旧セーブで空の外国人FA市場を補充したとき、生成年の既定値2026で生年月日が保存年度の年齢と不一致になる問題。2034年の実factory読込で8歳差のREDを確認し、読込/新規開始へ年度を渡す修正後、関連6ファイル64件が成功。

別コンテキストの独立レビュアーは実際のbase548モジュールで旧保存3状態を生成し、修正前の誤判定と修正後の580日/端数保持/行使回数/履歴不変/JSON冪等を確認。最終時点で未解決P0/P1/P2なし。[固定された旧snapshot/保存fixture](../../../src/engine/__tests__/fixtures/)を回帰へ残した。

資格snapshot単体の歴史検証は現在所属に依存しない。ただしapproved申請は市場未接続の進行ガードを維持するため、**approved申請を市場で完了して退団・翌年度へ進む全体フローを検証済みとはしない**。

## 実行結果

対象ファイルの回帰、実保存のinline/外部root・公開失敗/再試行・採用中断/復旧・履歴改変拒否、旧v1 frozen履歴の復元/replayを実施。初期化の既存フィールド/RNGハッシュは維持し、追加資格フィールドは専用検証へ分離した。

全件実行の初回にはsandbox由来の子プロセスEPERM/ローカルHTTP制限を確認し、ネットワーク権限付きで既存11件を再実行して成功。テスト/timeout/skip/CI構成の緩和は行わない。全件中に見つけた旧「無資格でも手動FA」fixtureは、資格あり/自動宣言なしの明示fixtureに直し、無資格拒否の新回帰を追加した。

提出前build成功（既存mixed-import/large-chunk警告）。関連23ファイル740件のうち一度失敗した再取得中選手のfixtureは、通算値でなくcycleStartDaysからの残高を設定する形へ修正し、国内/海外FAの2ファイル80件を再確認。追加修正後のbuildも成功。直前HEAD `b7b9e9a87e969f6feae6693865a9030c66049ef3` のCIでは328ファイル、4,269 passed/既存2 skipped。最終の全unit/integration・Chromium/WebKit E2Eの正確なHEADの結果とCIリンクは[提出PR #549](https://github.com/shotaro-hue/baseball-manager/pull/549)を正本とする。ローカルの変更途中の全件結果を最終成功扱いしない。
