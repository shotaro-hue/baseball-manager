# UI-04A 検証記録

実施日: 2026-10-19。基準main `3f8f414d9e5d35938b21dc33b607379e5e2f26a2`（#481マージ済み）。[要件・工程別完了条件](../../implementation/ui-04.md)／[実装計画](../../superpowers/plans/2026-10-19-ui-04a.md)。独立PRのheadとCIの確定結果はPR本文に記録する。

## 実装範囲

- 主分類をホーム/編成/日程/成績/経営へ統一。PC・スマホは同じ定義を使用。
- 経営の概要/補強/契約/財務。概要・補強トップは既存機能へ移動できる暫定入口。予算は実stateを表示し、給与前利益や現金と混同しない。
- 全9機能を移設。通知入口は未読と要対応を別表示し、既読の未解決提案を保持、配達前メールを除外。一般ニュースの既読データは存在しないため生成しない。
- 通知/設定/選手詳細からの外部遷移には元画面へ戻る入口とブラウザ履歴を接続。隠した元本文は保持し、FAフィルタ・選択・フォーカス・スクロールを復元。
- メール→既存トレード画面へのリンク。受信箱の選択をIDで保持し、外部画面で解決したメールは実mailboxの状態を表示。UIだけで成功扱いにしない。
- 編成エラーは閲覧を妨げず、試合開始時の検証を維持。保存状態は全ヘッダーで既存の実保存追跡を使用。

財務本体・契約/補強本体・受信箱/ニュース/OB本文のDES-01移行、FIX-M2、旧セーブ移行、給与/CPU/取引ルール、保存スキーマ変更は含めない。

全Vitest・既存CI対象の進行/年度/保存等は同一headのCIで確認し、Work側で重複全件実行しない。ローカルChromiumのナビ10件と追加視覚1件は成功。初回CI `39243554312` は新ナビ14成功・8失敗、財務/取引30成功、保存17成功。WebKitの全幅/通知8件の再読込クラッシュと、一部のスクロール復帰タイミングを検出した。失敗を成功扱いにせず次の修正を実施。

- `pushState` 履歴を戻った後のHTTP再読込で、ゲーム/React/保存を含まない最小ページでもWebKitがクラッシュ。同じ条件のネイティブフラグメント履歴では成功。[独立再現](../../../scripts/repro-ui04-history.mjs)は両方式の結果を出力する。Data URLの対照は成功したため、単なる全再読込不可とは区別した。
- アプリは `#hub/<tab ID>` のネイティブ履歴を作成し、そのエントリーへ既存UI状態を付ける。`pushState` を使わず、戻る/復帰/保存スキーマは維持。URLは一時UI履歴で、セーブや外部ディープリンクを追加する変更ではない。
- Hub表示中のブラウザ自動スクロール復帰とUIの復帰処理を競合させない。復帰フレーム完了後に一度末尾へスクロールし、レイアウト完了後に同じナビ重なりassertionを実行する。期待値や検証範囲を弱めていない。
- 比較Viteの共有prebundle衝突による504/React二重読込は別の検証環境問題。比較スクリプトのcacheDirを分離した。

初回CIのVitestは1,500成功・1失敗・既存2skip。唯一の失敗は `tests/roster-automation.test.js` がHubShellの離脱ガードのソース文字列を必須とする古いassertionだった。UI-04Aは編成エラー中の閲覧を明示的に許可するため、実際の `prepareTeamForGame` で指定守備位置の正しい編成を受け入れ、重複守備位置を拒否する正負の検証へ置換した。既存のゲーム開始検証・不正編成の拒否・新規の閲覧回帰は保持する。テスト削除/skipや成績閾値の緩和ではない。

履歴修正後は、関連Vitest47件、WebKitの360/390px全機能と通知→取引→復帰→保存再読込3件が成功。Chromiumの対応する視覚/761px/通知3件も確認。更新した編成回帰8件とビルドを再確認し、修正後headの全CIで受入を行う。

修正後の最終件数と同一head CIはPR本文で確定する。WebKitのOSライブラリはscratchへ展開して実バイナリを起動し、CIは標準の `playwright install --with-deps` を使用する。旧headの成功ジョブを新head全体の成功とは扱わない。
