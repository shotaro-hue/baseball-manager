# A1-2c-2b 期中解雇の検証

基準main: bd73308a00fbfda9c9cfd875e78c96e7e114ba94（#538マージ後）。

## 対象と正本

v2/season の enter-market/releaseを既存の冬の退団取引に追加する。worldの契約時計とgameDayを使い、gameDayは一時投影のみ。所属を削除した後の保有選手で両軍を成立検査し、証明用配置を採用しない。選手の能力、残る選手の一軍/二軍配置と待機を維持する。解雇を理由とする新たな10日待機は設定しない。

雇用は当日で終了し、支払・保証残額は既存台帳のretainで保持する。元契約単体の通知日雇用から退団証跡を検査し、再雇用後に旧契約を全台帳へ復活させない。市場・履歴・留保取消・receiptを一つの候補で更新する。人向けpending更改と受諾済み将来契約は拒否する。

## A1-2c-2b-FIX: 通知日と公式戦日程の照合

レビュー対象e5a9945で、100ラウンド/7月16日の退団履歴とreceiptのgameDayを両方99へ変えると、正本の99ラウンドが7月15日でも保存検証を通ることをVitestで再現した。初回3件のうちこの1件がRED（正常例と履歴だけの改変拒否は成功）。

engine単体には日程の正本がないため、annualDeparturesのworld境界検証をcontractEconomyのenvelope検査へ追加した。当年はworld.schedule、過年度はmatchHistoryが保持するscheduleArchiveの該当年度を使い、既存economyClockForで実日付を読む。日付をラウンドから推測せず、engineへ日程を複製しない。履歴/receipt/元契約/市場/終了actionの既存照合は維持する。

提供された日程の欠損・不正日付・別ラウンド・All-Star・通知日不一致は拒否する。過年度日程そのものが未保存または5年保持の対象外なら追加の日付照合だけを省略し、正常な旧保存の互換性を保つ。同じ年度の複数日程があれば全てと照合する。過年度日程がない場合、履歴とreceiptの整合性は検証できるが、そのgameDayを独立した日付証拠で証明することはできない。日程自体の同時改変に対する認証は本工程の対象外。

対象30件と保存5件がGREEN。通知日/roundの正常例、片方/両方の改変、範囲外round、不正/欠損日程、冬に残る期中履歴、過年度日程と欠落時の互換、同日/後日の再雇用、年度移行後の給与/保証行の不変を確認。createInitialTeamsとgenerateSeasonScheduleによる実データの正常/改変拒否例も含む。実保存ではIndexedDBのmatch-history chunkから過年度日程を復元して正常に再開でき、改変候補の保存拒否時に既存rootを維持することを確認した。

関連回帰は冬の退団・成立判定・台帳・更改・FA・年度予算・migration・保存commitを含む33ファイル1367件成功。npm run build成功（既存のbundleサイズ警告のみ）。公開ゲート、schema/DB version、給与/保証計算は変更していない。提出HEADの独立レビューと必須CI結果はPR本文に追記する。
