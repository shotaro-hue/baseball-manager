## 原因と修正範囲

1. **二軍の固定選考**。通常の能力優先から外れた健康な野手へ、当年の実測二軍Gが通常9人全員より少ない場合に最多1人のDH機会を設ける。投手は通常の休養・状態条件を守り、実測BFの少ない候補へ先発機会を回す。移籍前も合算し、旧推定は使用しない。`farmSelectors.js`／`farmSelection.js`。
2. **年度の見直し日持越し**。前年141日目等が残り翌年の定期見直しを止めるため、年度更新の保存候補で打線・編成の日付だけを0へ戻す。元の方針別・14日の周期を維持し、保存失敗時は当年度のまま。`useOffseason.js`。
3. **強い一軍控えの固定**。通常の評価差入替の後、実際の定期全自動レビューでのみ、実測main PAが0でfarm PAも代替候補より少ない控え1人を交換する。両DHモードの8守備先発、主捕手同士／非捕手同士、最後の健康な二軍捕手、育成・故障・登録待機・外国人枠・使用済みIDを保護。`rosterAutomation.js`。`seasonBatchCore.js`／`singleDayCore.js`／`useSeasonFlow.js` は実測contextを供給し、戦術の試合後には完了したばかりの二軍記録を使う。

65／32・33／捕手6／CPU通常67／上限70／通常10点・例外20点は変更しない。成長・給与・契約の式も維持し、既存セーブの所属・主位置・履歴を一律移行しない。既に旧版で年度更新済みの途中セーブの日付は、次回年度更新まで旧値を保持する。

## 計測の意味・制限

- **出場0**は一軍PA/BFと二軍PA/BFがすべて実測0。初年度だけでなく途中年からの連続0も全受諾指名IDで追う。退団・所在不明・自球団所属をCPUの0年度へ補完しない。未記録のPA/BFは集計エラーとし、推定0にしない。最終2035年指名の翌年は対象外。
- 捕手は主位置が捕手の支配下人数。CSVはオフ後人数と開幕人数、全守備位置・投野・育成、指名/受諾/拒否、明示終了理由、FA/支出、一二軍別新人PA/BF、予算/年俸、人員異動を含む。`endReason` 空欄は未記録で、後付けで「枠満杯」としない。指名数と拒否数は全年度記録している。
- FA入札ごとの残り新人予約人数・予算は逐一保存していない。実際の獲得人数・理由・予算推移に加え、連続獲得、受諾済み指名、拒否・育成の別計上、最低新人年俸留保の回帰テストで補完する。育成昇格とCPUの入団拒否が自然発生0なら、実行したとは扱わない。
- 保存再開は全12球団の所属・契約・二軍記録・年次履歴の同一性を照合する。永続一軍球歴の年度集合は、記録対象となる自球団選手を期待値と比較する。CPU全IDの過去全球歴を外部DBから読み直す網羅検査とは区別する。二軍のみの年度を架空の一軍球歴にしない。
- `playerUsage.current` は既存診断の捕球能力で、総合評価や打力ではない。ここから成長停滞を推定しない。
- **ポストシーズン大会は迂回**。大会UI・優勝収益を含む完全App10年旅程、実機Safari、すべての人間編成方針は対象外。旧原本とのNode版の差も明示し、RNG/ID経路が変わるため同一選手・勝率・処理時間の厳密な対比較やバランスの最適性を主張しない。旧PRの当初2年は同じNode24でも元の結果を再現した。
