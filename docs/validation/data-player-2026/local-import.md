## 到達点と公開版の区別

標準同梱の実在選手は445名のまま。公開再配布の確認が済んでいない全件データを `release.json` に入れていない。
追加した経路では、タイトルの「選手名簿ファイルを使う（新規ゲーム）」から正規化JSONを選択し、球団を選ぶと、その全選手を使う新規ゲームが作られる。ファイルを選ぶだけではセーブを変更しない。開始・初回保存は既存の一括確定処理を通る。「続きから」は名簿を再読込・注入しない。

公式登録公示を登録日・抹消日で復元した開幕名簿は1,059名（支配下791、育成268）。既存445名とのID対応を保持し、追加候補614名、削除0名。各球団の人数は既存の [照合報告](README.md) の「公式公示候補」と一致する。

全1,059名の個人プロフィールを取得し、生年月日・投打と恒久IDを照合。706名に計3,725行の2025年以前の一軍年度別成績があり、残る353名に架空の成績行は作らない。登録公示の全ID・球団・区分を独立したパーサーでも再抽出して照合した。これは異なる資料による二重確認ではない。外部名簿には出典1,097件を記録し、原本を保有する1,095件はSHA-256も付す。

少数の個別確認値は `playerMaster2026Facts.js` へ分離。ビシエド・ソト・モイネロの2025年国内FA資格公示を外国人枠免除の根拠とし、モイネロの2025–2028年契約・年10億円相当は2024年3月28日付報道として記録する。年俸の公式発表値と扱わない。名簿内では年俸・契約1名が報道値、1,058名が未確認のゲーム設定。外国人枠は国内959、免除3、対象1、不明96で、不明分のゲーム用フラグと資格の事実を分ける。

`localImport:true` は明示された外部マスタの読込だけに使用する。人数、ID、12球団、登録区分、支配下70名、出典URL、属性型、年俸単位、契約年、2025年以前の成績、アウト数の検査は維持する。公開用 `stage.mjs` と標準同梱マスタは利用条件の検査も維持する。ローカル読込は権利上の許諾を与える機能ではない。

## 更新手順

原本HTMLは公開リポジトリへコミットしない。Python 3と `lxml` を使用する。

1. `registration.mjs` で公式登録公示24ページから開幕所属の参照ファイルを生成する。
2. 12球団の選手一覧を `team_s.html` 等、2025年守備表を `fielding_s.html` 等にローカル保存する。球団コード順は `s,db,c,t,g,d,h,e,l,m,f,b`。
3. 参照ファイルにある各NPB IDの個人年度別ページを `profile-<ID>.html` として保存する。全員分がない場合は抽出を中止する。
4. 以下で新しい候補を作る。既存原本・既存候補を上書きしない。

```bash
python scripts/player-master/extract-facts.py /path/to/private-html /path/to/opening-reference.json /tmp/facts.json
node scripts/player-master/assemble.mjs /path/to/opening-reference.json /tmp/facts.json /tmp/master-candidate.json
python scripts/player-master/extract_facts_test.py
```

5. 選手単位で所属・登録区分・安定IDと属性差分を確認する。候補は `status:candidate`、球団証拠は `verified:false`、出典の公開条件は `unconfirmed` のまま出力される。実際の所属検証後だけ前二者を確認済みに変更する。給与・契約等の推定区分を確定値へ変更しない。
6. 外部名簿を使った初期化・契約・試合・保存・再開を確認する。公開利用条件未確認のファイルは標準同梱へ昇格させない。

## 取り違えを防ぐ処理

- 現在の球団一覧は生年月日・投打の照合に使用し、開幕所属の根拠にしない。開幕後に退団した6名も個人ページで照合する。
- 成績は氏名や外国人の略称で結合せず、NPB IDごとの個人ページから取得する。「マルティネス」「ゴンザレス」等の同姓別人や、投手の打撃行を野手へ混入させない。
- 2026年以後の行は除外し、それ以前の履歴を保持する。投球回の `.1` / `.2` を整数アウト数へ変換する。アウトを取らず降板した `+` は0アウト、`----` の防御率は欠測として保持し、失点・自責点は捨てない。
- IDのない2025年守備表は、氏名が一意に対応し、個人履歴で同年同球団への在籍を確認できる場合だけ使用する。外野3位置の区別や実績不足の適性はゲーム推定として表示する。
- 捕手表など、同一HTML親要素の複数表を最初の見出しに結び付けない。各表の直前の見出しを使用する。
- JSON履歴の球団名にオブジェクトを渡して画面を壊す入力は、読込時に拒否する。
- 投打が不明な入力は読込時に拒否する（投は right/left、打は right/left/switch）。右投げ・右打ちへの暗黙の補完をしない。今回の1,059名は全員確認済み。
- 正規化名簿の未記録成績は保存後も `null`、実測0は0。`stats.recording:observed` を付して旧形式のゼロ補完と区別し、年間・通算表示とグラフで欠測を0に置き換えない。通算の一部が不明なら合計も不明のままにし、新人資格や通算記録を断定しない。新しいシーズンを加算しても不明値を保持する。旧セーブの履歴にこのマーカーを自動付与しない。
- 投手の通算率は取得できた実測カウントから計算し、0アウト登板の失点等の分子を落とさない。旧形式の率しかない履歴は既存の率による表示経路を維持する。

## 検証と未達条件

ローカル読込から900名の合成名簿がルーター、初期化、保存、再開まで届くE2Eを既存の初期化CIへ追加し、Chromiumとmobile-webkitの対象とする。実在名簿の一括配置経路についても1,059名・育成268名・一軍育成0、360/390/1280px、保存再開での全ID維持を確認。クラウドChromiumで初期化約1.1–2.4秒、保存状態のJSONは約4.8MB（圧縮前）。同期/非同期の全チームオブジェクトも同じ乱数系列で一致した。初回保存後のブラウザ申告使用量は約574KB、localStorageは1,080 bytes（UTF-16換算）。端末性能・iPhone実機の保証ではない。

実在名簿で1,059契約の年額・残契約年数の一致と12球団1日6試合を確認。FA候補を空にした分離試験では試合後も1,059名を保持した。通常ゲームのCPUによるFA加入は初期名簿の架空補充とは区別する。

既存 `annual-journey.spec.js` の開始操作だけを実在1,059名のJSON読込へ置き換えたローカル検証がChromiumで成功（約3.2分）。実UIによる143試合、全12球団の勝敗・結果数・二軍進行、101試合時の保存再開、ポストシーズン、契約更改、ドラフト、2027年開幕、保存再開、翌年最初の1試合まで検証。保存を捏造した終盤fixtureではない。既存の全アサーションを維持し、ブラウザエラー0。全選手の何十年ものバランスや実機Safariの保証ではない。

実保存の経歴アーカイブも706名・3,725行を保持し、年・球団名が原データと一致。投手1,759行は保存後の投球回を3倍して原本の整数アウト数と一致した。

`6bf8d26` のCIで初期化スナップショット3件が失敗。修正前後を同じ3シードで生成して全フィールドを比較した結果、各シードの差分はビシエド・ソトそれぞれの外国人枠フラグ・免除区分・出典精度の3項目のみ。給与、契約、乱数消費、全ID、編成など他の全項目は一致した。根拠を [quota-snapshot-audit.json](quota-snapshot-audit.json) に保持し、この2名の免除を明示アサートしたうえでスナップショットを更新。失敗をskip・削除していない。

全件の権利確認、年俸・複数年契約、外国人枠、FA開始日数、新人/海外/二軍実績、外野の詳細適性は未達。未知の給与・契約は既存値を明示して保持するか、登録区分別のゲーム最低値・単年を使用する。既存値がゲーム最低値未満の場合だけ最低値へ補正する。未知の外国人枠は未知のまま明示し、ゲーム用フラグと区別する。

**全選手データ再構築の受け入れ条件を全て満たしたという報告ではない。** 最新コミットのCI結果はPR本文で追跡する。
