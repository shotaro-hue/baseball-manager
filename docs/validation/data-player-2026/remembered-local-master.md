# 端末内の選手名簿を次の新規ゲームでも使う

2026-10-31、PR #525 マージ後の `432e99c` を基準に実装。

## 到達点と使い方

標準同梱は445人のまま。**全1,059人の公開標準収録は未達成**。
今回は、利用者が自分で選択した名簿を端末内に記憶し、次回以降は再選択せず新規ゲームに使えるようにした。

1. タイトルの「選手名簿ファイルを使う（新規ゲーム）」で名簿JSONを選ぶ。
2. 「新規ゲームの名簿：1059名（記憶済み）」を確認し、球団を選ぶ。
3. ページを閉じても、同じブラウザ・同じサイトの新規ゲームで再利用する。
4. 「標準名簿に戻す」は端末の名簿選択を解除する。既存セーブの選手を置換したり、セーブを削除したりしない。

名簿ファイルを公開リポジトリやネットワークへ送信する機能は追加しない。元のファイルは手元に保持する。別端末への移動、ブラウザデータ消去、保存領域の削除後は再選択が必要。名簿自体はゲームのバックアップに含めないが、既に開始したゲームの選手は従来どおりセーブに含まれる。

## 保存と失敗時の動作

- ゲームの保存DBから独立した IndexedDB `npb-player-master-v1` に名簿JSONを1件だけ保存する。
- localStorageには選択済みを示す1文字だけを置く。未選択の通常タイトルではDBを開かず、従来の軽い「続きから」を維持する。
- 復元時も8MB上限、1,500人上限、12球団、支配下70枠、重複ID、2025年以前の成績、明示されたゲーム用仮設定など既存のマスタ検証を実行する。
- 読み込み中は新規ゲーム開始を止め、標準名簿で先に開始する競合を防ぐ。保存領域が応答しない場合は3秒でエラーにし、操作を戻す。
- 端末への記憶が失敗した場合、読み込んだ名簿はその画面での新規ゲームに使えるが「記憶済み」とは表示しない。
- 差し替え時は旧選択の自動復元を先に解除。不正ファイルの選択後やDB消去失敗後に、次回起動で旧名簿を復活させない。
- 壊れた保存内容や選択マーカーだけ残った場合、標準名簿であることと再選択が必要なことを表示する。
- 他タブで後から名簿を選んだ場合、その選択は次回のタイトル読み込みから反映する。進行中のゲームを変更しない。

## 公開同梱について確認したこと

復元した完全名簿は1,059人、支配下791人・育成268人、出典1,401件。今回、選手の追加・削除・所属・契約・能力の変更はない。人数や802人の報道年俸等は [前工程の報告](reviewed-contracts.md) と同じ。

- [NPBの実際の成績ページ](https://npb.jp/bis/players/41545153.html)には情報等の二次利用・無断転載を禁じる表示がある。
- [文化庁](https://www.bunka.go.jp/seisaku/chosakuken/seidokaisetsu/chosakukensha_fumei/)は単なる事実・データと著作物を区別している。個々の数値や氏名について一律に許諾が必須とは断定しない。
- [著作権法第12条の2](https://laws.e-gov.go.jp/law/345AC0000000048)は情報の選択・体系的構成に創作性を有するデータベースの保護を定めている。
- 完全名簿に含む基本属性・登録履歴・年度別統計を、今回の形で公開ゲーム・公開リポジトリへまとめて配布できる根拠は未確認。確認済みと扱う変更はしない。
- `playerMaster2026.release.json` と公開向けコンパイルの権利確認は変更しない。端末内記憶は既存の明示的ローカル読込経路だけを再利用する。

次の公開同梱判断では、基本属性と年度別数値を独自のゲーム用構造へまとめた配布内容について、利用条件の確認または適法性の専門的確認が必要。原本HTML・写真・ロゴを含める計画ではない。

## 検証

- 関連6ファイル60テスト成功。未選択タイトルが履歴DBを開かない既存の回帰条件を維持。
- Chromium E2E 2件成功: 記憶、再読み込み、自動選択、ゲーム開始、保存再開、標準へ戻す、不正ファイル差し替え。
- 実際の1,059人ファイルでも同じ新規ゲーム・保存再開経路を確認。1,059固有ID、育成268人、一軍の育成0人を維持。試験用ファイルは公開コミットに含めない。
- ビルド成功。360 / 390 / 1440pxの変更前後で横はみ出し・pageerrorなし。[画面検証](remembered-ui/results.json)。画面用は架空900人の検証データ。
- ローカルWebKitはOSライブラリ不足で起動不能。Safari系はPRのGitHub CIで確認し、結果はPR本文へ記録する。実機iPhoneの確認とは区別する。
- 選手・契約・試合計算・年度更新を変更していないため、ローカル全テスト・年間進行の重複実行はしない。最終headのCI結果を利用する。
