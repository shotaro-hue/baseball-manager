## 実装と範囲

人的補償の最初のPRとして、保護名簿を提出する共通取引と候補照会を追加する。`faProtection.js`が元の対象・保護ID・現在の候補・履歴の検査を担い、`annualTransactions.js`が全state検証、取引署名とreceipt、予算の非変更を担う。`MAX_FA_PROTECTED_PLAYERS=28`は一軍登録人数とは別の定数。オフの満了/将来契約や複数請求の優先順位を無理に通常トレードへ流さず、実移管/精算はG-2へ分割する。

FA補償案件（proposalId）ごとに1名簿を保存する。提出は受諾済みpendingのA/B案件に限り、同球団・同年度の別案件へ異なる保護名簿を提出できる。案件が後に金銭精算済みでも、その歴史名簿は消さず、他案件の名簿も変えない。提出日・元の対象はstateから決める。保護ID入力は型を保って順序を正規化する。snapshot/receiptは別コピーとし、片側の変更を共有参照で隠さない。

現在の一軍/二軍を母集団とし、外国人/育成/引退/FA/戦力外/当該新人を除外する。同オフのFA・トレード加入者は実所属なら含め、受諾済み未入団FAは含めない。入団済み新人はドラフト情報と契約台帳に照合されるrookie受諾履歴の世代で区別し、pool消去・トレード後も除外する。既存選手の獲得契約、同年途中加入、負傷、満了や翌年更改は誤って除外しない。保存した名簿は履歴として保持し、現在も対象である元の非保護IDだけを候補として返す。後から加入した選手を足さず、失われた元の非保護候補をunavailableへ示す。候補は移管の受理保証ではない。

2009年FA規約第10条とリーグ運営の解説で28名・外国人除外・補償方式・競合優先順位を確認した。旧規約を現行最新版とは扱わない。直近新人の除外・直近FA/トレード加入者の対象化・異なる旧球団への異なる名簿は設計書に挙げた報道解説で再確認した。0〜28名と現在stateを用いた候補再審査はゲーム側の簡略化である。現実の公示名簿の全履歴・提出2週間/精算40日の自動処理・制度改定案の採用は行わない。
