# GM-01C-1 — 共通取引とFA・トレードの代表経路

2026-10-27。base main `e591de1428020da0d42f9c3a88ab94146a03e8bc`（#506）。

## 今回の成果と境界

`annualTransactions.js`の見積・確定が、実名簿/FA市場、#506の契約台帳と年度支出審査を一つの不変状態として扱う。既存トレードの名簿移管・外国人/負傷者配置・打順参照整理を`projectTradeRosters`として共有し、既存の現行予算処理は同じ公開関数で継続する。

**本番の新制度有効化、既存hookからの新API呼出、保存形式の変更はまだ行わない。** 次はC-2で手動/CPU/委任/Workerの全取引を接続し、Dで年度配分・更改・保存/冷起動・UIを揃える。

## APIと正本

- `quoteAnnualTransaction(state, command)` → `{ok, rows?, error?}`。候補stateを返さず、元stateを変更しない。
- `applyAnnualTransaction(state, command)` → `{ok, state, rows?, error?, replayed?}`。最新stateで再審査。失敗時は元stateと同一参照。成功時だけ名簿・市場・台帳・留保・支払/受取・取引receiptを一緒に返す。呼出側は結果state全体を一度に採用する必要がある。
- State: `version:1, season, date, phase, teams, faPool, spending, rosterRequirements, draftContext, transactions`。既存ゲームstateをそのまま渡せる移行関数ではない。
- Commandはcallerが一度発番するIDを持つ。`offer-fa(proposal)`、`accept-fa/cancel-fa(proposalId)`、`trade(fromId,toId,outgoingIds,incomingIds,cashManYen,mode)`。同一IDの同条件再送はJSON再読込後もno-op、異なる条件は拒否。失敗したIDは確定しない。
- 金銭は万円の安全整数。tradeの正値はfrom→to。支払/受取と全契約移管のIDは取引IDから決定的に派生し、片側や別取引の金銭をcommandに渡せない。
- 既存`team.budget`は更新しない。新制度の金額の正本はspendingのみ。年俸/残契約表示は契約と有効レートから導出する。

## 実名簿からの最低維持費

`rosterRequirements`は上流の編成計画が持つ球団/年度別`requiredControlledCount`。commandからの書換えを受け付けず、全許可年度への明示を要求する。67人への固定や新たな人数政策をこのPRで決めない。

現在は実名簿と有効契約の所属一致を要求し、将来年度は2/1時点の有効契約と留保から支配下選手IDを重複なく数える。退団後の保証債務や育成選手は人数を満たさない。人数不足×既存最低支配下年俸420万円を導出し、入力のminimumRosterReserveManYenを信用しない。当年度の受諾済み未所属新人も、未確保の人数分を最低費用へ残す。契約/留保で確保した新人は二重に数えない。

この最低人数費用は、個々の新人の要求年俸やポジション別編成計画を代替しない。実際の新人合意額はC-2でrookie留保へ接続する。現在のdraftContextは当年度分だけで、将来の未合意新人を推測しない。必要人数の決定、故障による緊急補充、役割制約の接続もC-2/Dに残る。

競合敗退/取消で復活する最低維持費を新規契約支出と誤認しないよう、通常審査では最終の派生最低費用を共通にして契約増分を判定し、トレードについて別途実際の前後余力を比較して赤字悪化を拒否する。取消/競合敗退では、月割り留保より大きい保守的な通年最低維持費が復活しても、新規支出がない限り解放を認める。勝者の新規契約は年度別審査を通す。無金銭例外は#506の全年度非悪化審査をそのまま使う。

- JSON再読込後の再実行、条件違いのID再利用、凍結入力、古い見積後の予算変更を検証。
- 退団保証、無関係の新人留保、赤字の競合敗退先、外国人/負傷者の二軍配置を検証。

## 限定と次工程

今回のFAは支配下、1〜3年、開幕前/公式戦中の同日有効オファーが対象。日付が進んだ提示は明示的に取消して当日条件で再提示する。非同期回答を受け取る日の効力・留保更新、オフの翌年加入、更改、育成契約、新人加入、発掘、支配下化、引退/終了はC-2/Dで個別に接続する。CS等の登録スナップショット・臨時収入も未接続。

原子性は単一不変state候補の構築についての保証。実ストレージへの永続化、複数タブ競合・クラッシュ回復・新制度の実画面受入を検証済みとはしない。

## 合成負荷の観測

12球団×65人（780人）、全員7年契約、全84年度枠の無金銭交換見積を同じローカル環境で観測。各年度の雇用集計を球団ごとに繰り返していた処理を、単一の最低維持費算出内だけで日付別に再利用し、3,433ms→688ms。既存133件の結果は同じ。永続キャッシュや失効管理は追加しない。単発の合成測定であり実iPhone/実CPU全経路の性能保証ではない。全経路接続時は見積頻度と実人数で再計測する。
