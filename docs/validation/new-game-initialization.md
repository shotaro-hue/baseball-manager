# 新規ゲーム初期化・E2E待機

作業日: 2026-10-09。開始main: fb1fb59053222f9ffd8582932b11d27315d91ae0（PR420マージ済み）。
添付ZIPは古いため、GitHub mainの360 blobをSHA照合して復元。作業開始treeは66b7c31e26166f7f9cbe3bd95e13a18a2d65093cで完全一致。git通信が使用できず、取得・PR更新はGitHub APIを使用する。main直接push・マージ・自動マージなし。

## 原因と変更

- 従来は12球団の同期生成・自動編成をまとめて実行し、処理中状態はrefだけで画面へ渡らなかった。既存E2Eはクリック後にtopbarを5秒待ち、初期化の失敗と表示遅延を区別できなかった。過去の初回失敗の具体的な負荷要因は未確定。
- CPUプロファイルでevaluateBatterForPolicyおよび呼出先の重複を確認。回帰条件では同じ選手を打順生成で最大29回、編成推薦で196回評価していた。変更後は打順計算内1回、推薦と前提打順計算を合わせ2回以下。評価式は変更しない。
- idle/initializing/ready/errorの一時状態を公開。TitleScreenにrole=status、aria-busy、失敗時role=alert、操作disabledを追加。同期refでも古いcallbackを防ぐ。最初のCPU処理前と球団間でrequestAnimationFrameの後にタスクへ制御を返す。
- 同期/非同期生成は同じ球団生成関数を同じ順序で使う。キャッシュは打順計算/固定チームの編成推薦に閉じ、選手参照をキーとする。投手評価・方針評価式・乱数・ID生成・所属・打順・守備・投手編成は変えない。
- 球団・FA・日程の準備をローカルに完了し、実IndexedDB履歴保存が成功してからReact stateとホームを公開する。保存は省略しない。保存API/DB構造は無変更。
- 独立レビューで先行ロードの古い結果が新規ゲームを上書きする競合を発見し、実Appテストで再現。初期化開始番号でロード/削除を失効させる。既に開始したロードは履歴移行の可能性があるため、完了を待ってから新規生成する。読込失敗/日程準備失敗をホーム遷移として扱わない。
- 新規開始を使う全E2Eを共通waitForNewGameReadyへ統一。明示的ready/errorを有限15秒で待ち、エラーなら直ちに失敗。続いて球団名・保存・ホーム試合操作を確認する。全体timeout、retry、skip、固定sleepを変更しない。初期化固有15秒の根拠は以下の計測。

## 実行履歴の扱い

過去PR420の全E2E「36成功/1失敗」は独立した過去記録として維持する。今回の結果で置き換えない。
開発中のREDとテスト作成誤りは最終検証と分ける。初期ブラウザテストは球団一覧の先頭を巨人と思い込んだ誤りを修正し、日程は先頭ダミーを含む配列キー数でなく143試合/球団を検証するよう改めた。
最初のsmokeは実装変更中のVite HMR・並行検証が混在したため、最終headの合否として使わない。失敗ログ/traceを保持し、変更完了後の検証を別実行として記録する。
