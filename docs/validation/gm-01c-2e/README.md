## 変更と判断

- `acquisitionMarket.js`：国内FA/海外FA/自由契約の明示市場情報、提示日と回答日の整合性。既存faPool/isFAから市場種別を推測しない。`isForeign`は国籍/登録枠の属性であり海外FA権ではない。
- `annualSpending.js`：原提示の情報を留保/解決履歴に保全し、回答日を別記。オフの翌年2月1日は受諾しても変えず、期中は既存acceptedProposalで実加入日へ後進。拒否/取消/競合敗北で留保を解放。
- `annualAcquisitions.js`：既存資格と明示市場の検査、補償が必要なA/B国内移籍の受諾保留、オフ受諾の将来台帳確定・選手情報保全・翌春の二軍加入。加入済み情報は元所属ではなく履歴として保ち、後日のトレードを妨げない。
- `annualTransactions.js`：任意の加入履歴、加入待ちと名簿/台帳の照合、70人枠、新人との加入順、既存のfloor予算との接続。資格/引退の変化で新規受諾は拒否するが、未受諾提示の取消を妨げない。

既存の正当な未記録同年度FAは旧API/data形を維持。新しいオフ提示は明示市場/提示日を必須にする。全体stateの外部認証を新設したものではなく、暦/phaseは将来の呼出側が正しく供給する必要がある。

## 本番接続と残課題

**本番未接続。** 今回の新市場情報/加入履歴/支出台帳を実ゲームのhook、CPU、委任、Worker、旧セーブへ自動追加しない。本番画面・海外志向による離脱・外国人生成/市場の春更新・契約更改/新人加入/予算配分の旧経路を維持する。JSONテストは新基盤stateを対象とし、本番の新制度移行が済んだことを意味しない。buildの同一性も実iPhone性能の検証ではない。

A/B補償は現行コードに実処理がないため、他球団移籍を無補償で成立させない。人的補償/金銭補償と年度別費用、FA獲得人数上限、海外移籍/NPB離脱の共通取引化、宣言公示の具体的カレンダー、権利再取得/145日制度への換算は後続で設計/一次資料を再確認する。今回、資格式を根拠なく変更しない。

回答期限・自動失効は未実装。原提示・回答日とterminal状態は用意し、日時だけで状態を変えない。未回答を開始年度より後の予算へ跨がせる前には明示解決を要する。加入待ちを残したまま開始年度のシーズンへ入ることも拒否する。本番年度更新adapterでの処理順・未回答の締め・契約の現在投影を次工程で接続する。

全体年度更新・旧保存移行・本番呼出順序・UI/コーチ・動的校正・実iPhone性能と完全バックアップ/復元は未実施。小さな追加モデルで今回の一巡を実装できたためE-1/2/3の別PR分割は行わず、本番未接続の一つのPRとする。マージ、auto-merge、main直接pushは禁止し、最終判断は利用者に委ねる。
