## 修正前の原因確認（コード追跡）

- `regularGameUpdates.js`: `applyPopularityDelta`・勝敗更新後の `updated` を `applyClubGameFinance`へ渡すため、前の試合で決まるはずの観客需要に当該試合の結果が混ざる。
- `tradeTransaction.js`: 双方の取引後予算に `>= 0` を要求するため、運営費で予算が負になった球団は無金銭の選手交換まで拒否される。
- `clubFinance.js`: 累積レジャーと年間配賦は整合し、負の`operatingSurplus`を認めている。この形式は変更しない。
- `saveload.js`: 収支レジャーの検証は負の`budget`それ自体を不正扱いしない。年度配分は既存の下限と給与集計を使用する。
- 単日/まとめWorkerと通常シーズンの入口は同じ`applyRegularSeasonTeamUpdate`を通るため、修正場所を共通更新関数へ限定できる。
