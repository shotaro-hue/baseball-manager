## 複数年度・保存再開

[共通検証](../../scripts/qa-d1-offseason.js)（seedごとの3 testファイルから実行）／[年度・保存地点別記録](../validation/qa-d1/offseason.json)。React test renderer上で実`useGameState`・`useOffseason`・`simulateSeasonBatch`・`saveGame/loadGame`を使用し、ゲーム処理やhookをmockしない。NodeのMap localStorageとfake-indexeddbによる保存で、実ブラウザのストレージ容量・実機性能とは区別する。

進行は実143試合×12球団の通常シーズン→引退・成長・CPU更改／FA宣言→自球団更改・FA獲得・戦力外→六巡ドラフト→キャンプ→年度更新。ポストシーズン大会はこの複数年度測定から省き、既存の実App E2で大会から翌年度までの画面操作を別途確認する。自球団更改は合意後callbackを要求年俸で実行するため、全交渉分岐のUX検証ではない。

確認内容：全所属・市場のID排他、70枠、契約年数・年俸・年齢の年度更新、FA契約の一回払い、戦力外残留防止、ドラフト所属・二重適用拒否、全12球団143試合、二軍archive・日程履歴・表彰・順位表・IndexedDB通算記録。保存後にhookを破棄し、実`loadGame()`と復帰先判定で再開する。JSON保存の`-0→0`・undefined除去を正常な正規化として扱い、年度／所属／成績の欠落とは区別する。通算履歴の同一性は既存のyear/teamId/teamNameのキーを使い、同一年の異なる球団履歴を重複扱いしない。

3seed×3年、計9シーズン、42地点で保存・ロードして2029年開幕まで到達した。全年度で12球団各143試合を完了し、所属重複・70枠超過・履歴消失・更改／獲得／年度更新の二重適用は検出しなかった。seed15では毎年8地点、他2seedは毎年中盤・キャンプ・翌年開幕の3地点を確認した。二軍の未実施理由は全件`insufficient-catcher`で、二軍捕手を一軍の最低人数確保のため昇格させた後の層不足に起因する。未実施を日程消失や一軍進行停止と混同しない。3年目の登録枠充足に伴い指名人数が減る現象も記録した。CPUの捕手確保・昇降格と長期編成の改善候補として残す。

初回の単一ファイル連続試験はseed15/16の計6年を完了した後、3seed目でNodeの約2GB V8 heap上限に達してworkerが終了した。その実行全体を成功扱いにしていない。試験ケースをseedごとの3ファイルに分け、fake-indexeddbも各seedに独立生成して隔離した。seed17は単独で3年を完了し、最終head CIで3ファイルを含む全試験を再確認する。これはJSメモリ内DBのテスト環境の制約であり、実ブラウザ／iPhoneのメモリ問題の修正・安全性証明とはしない。各seed記録の時間も同時負荷が異なる参考値である。

旧セーブは既存のlegacy/部分欠損fixtureで調査ポイント0・観測済みレポート・途中再開の保全を確認する。実ユーザーの過去全バージョンのセーブファイルを収集しての互換性確認ではない。候補枯渇・満員・入団拒否・獲得の二重適用は既存draftRules回帰、手動と自動は既存draft-decision E2Eと今回の実フック連続試験で補完する。

## 画面・性能

ChromiumとPlaywright WebKitの360/390/1440pxを対象に、80人の通常生成候補でプレビュー、配分、絞り込み、並び替え、深いスクロール位置の復帰、詳細・2人比較、調査、指名確認、競合、後続巡、レビュー、途中保存・再開を確認する。操作journeyは自球団64・競合CPU69・他10球団70枠に調整し、抽選落選と再指名を再現する。12球団すべてが指名する検証は別の生成ドラフト測定。性能測定では元の12球団編成を使う。iPhone実機は利用できず、WebKitも実機Safariの証明ではない。

基準版Chromium390では、48回のスクロールで48回の親保存state更新、152回の候補描画、12,160回の公開順位ソートを観測した。スクロール区間約785ms、フレーム間隔p95約24.1ms。同じ48回のプログラムによるscrollTop変更・候補・viewportで修正後を比較する。併走プロセスによるhost負荷は隔離していないため、時間は参考値とし、描画／状態更新／ソート回数を主な根拠にする。開発版・React StrictModeの計測で、本番iPhoneのfps保証ではない。

変更：計測後、スクロール位置の参照と永続viewへの反映を分離し、更新を間引く。公開評価順位はimmutableな公開レポートmapをキーに再利用する。開く／保存する境界で最新位置を確定し、フィルター・戻り・アンマウント時の動作と新しい公開mapでの無効化を回帰で保護する。評価値・CPU重み・調査ポイント・保存形式は維持する。実測上の明白な進行停止や実機遅延を示すものではなく、P2の安全な性能改善として扱う。

## 発見事項と修正

| 分類 | 再現・影響 | 対応 |
|---|---|---|
| P0 | 検証範囲では進行停止・所属破壊を検出せず | ゲームルール・保存形式の修正なし |
| P1（独立レビューで検出した修正中の回帰） | PCの詳細表示中に並び替えるとDOM位置が戻らず、キーボードフォーカスが詳細見出しへ移る | フィルターの位置リセットと選択時フォーカス処理を分離。失敗テスト追加後に修正、両エンジンで確認 |
| P2 | 48回のscrollで31〜48回の親更新と5,760〜12,480回の順位ソート | 最新位置をrefに保持し150msで同期、公開mapのidentityで順位キャッシュ |
| P2 | PCで一覧へ戻るとfocusが深い位置を約3,000px動かす | preventScroll付きfocus。両エンジンのRED→GREEN |
| P2／後続バランス | 二軍捕手不足による未実施、3年目の登録枠充足 | 原因・件数を記録。CPU編成全体の変更は分離 |
