# FIX-M1 — 球団収支と編成予算

基準main `d8fe622`（#480マージ後）。[承認設計](../superpowers/specs/2026-10-18-club-finance-design.md)／[実行計画](../superpowers/plans/2026-10-18-club-finance.md)／[検証記録](../validation/club-finance/README.md)。

従来は残予算に比例した入場料がビジターにも入り、売上全額が補強予算へ加算されていた。新規ゲームと翌年度からは、球団別の動員と単価、主催興行、年間商業契約、自動運営費を共通計算で扱う。

## 処理と保存

- `clubFinanceProfiles.js`: 動員はNPB公式2025年平均。価格・商業契約・費用はゲーム推定値として一元化。
- `clubFinance.js`: 主催試合の収入、143試合の年間契約・固定費配賦、重複排除、予測、年度予算を純粋関数で計算。年度契約は累積丸め差分により最終額が一致する。
- `regularGameUpdates.js`: 通常・戦術・CPU・Workerから同じ年度/ラウンド/ホーム情報を渡す。新規初期化と`useOffseason`の年度更新で空のレジャーを開始。
- `saveload.js`: 新レジャーを検証し、破損時は既存の世代復旧へ送る。レジャー未導入の旧セーブは当年度の旧計算を維持。
- `FinanceTab`: 実績＋残り試合、6収入区分、運営費、給与前後の参考差額、編成予算を表示。日程未確認時は概算と明記。
- `useGameState`: 画面と同じ10/25/50億円の投資価格を使用し、最新予算を再確認して購入する。手動チケット価格は改修しても維持。

## 判断と限界

1. `budget`は編成予算の残枠。現金会計に変更しない。既存の契約・FA先払いと年度オーナー配分は維持し、年度配分の入力を売上60%から運営差額60%へ変更する。誤差が判明した場合は将来の配分方針を校正し、過去のセーブの現金を捏造しない。
2. 旧セーブは当年度の金額を保持して翌年度に移行する。新モデルへの反映は次シーズンとなる。初回の年度配分でも所属重複とID=0を正しく除外し、欠測年俸を0として扱わない。
3. 動員以外の単価・原価・商業契約は実在球団の公表決算内訳ではなくゲーム用推定。日本ハムのボールパーク事業決算は非試合日事業を含むため、球団単独の売上として一致させない。
4. 現行の実日程では球団ごとの主催数が69〜74試合となる。日程生成を変更せず実データを予測に使う。日程が確認できない場合の71〜72試合は確定数ではなく概算。
5. 経営画面全体のDES-01移行、選手選択AI、税務・借入・球場所有・ポストシーズン興行は今回の対象外。給与を重複控除しない簡易収支であり、完全な損益計算書ではない。
6. 承認済みの設計を同じセッションで実装し、mainとは独立した未マージPRとして提出する。レビュー指摘の給与集計・不正日程・手動価格の説明は回帰テストで修正前の失敗を確認してから修正した。
