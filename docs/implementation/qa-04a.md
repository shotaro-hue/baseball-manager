# QA-04A — UI刷新後の進行・保存の総合検証

2026-10-25。#501マージ後、利用者の「マージしたから進んで」に基づき、既存UI-04工程の次のQAを実施する。基準mainは `e1cb7ab0511bd36a8ee81a9a7789a606a62efb7c`、treeは `472054415c34e5b044e3cbb9d158d76545725243`。

## 目的と方法

新規ゲームから試合、編成・成績・経営、オフシーズン、翌年、保存再開までがつながることを確認する。既存通常CIは同一sourceの成功結果を再利用し、通常CI外の全8spec・20ケースを追加実行する。さらに、結果を埋めた終盤fixtureとは別に、初日から143試合を実Workerで進め、年度更新と翌年初戦までを通常UIで操作する固定seedの旅程を追加する。

全E2Eを同じ環境で重複実行する方法は、通常CIが既に保護する大量の同一操作を繰り返すため採用しない。保存データを直接終盤へ書き換える方法は既存E2で保護されており、今回の実進行の証拠にはしない。

## 受入

- 通常CI外8specの20ケースをChromiumで実行し、失敗を製品・旧UI依存・環境に分類する。必要な継続ゲートを通常CIへ追加する。
- 新規→試合進行→143試合終了→ポストシーズン→引退/編成計画→FA→ドラフト→年度更新→キャンプ→翌年初戦をChromiumと390px WebKitで操作する。
- 中間・翌年に実保存/再読込し、12球団の勝敗・所属ID・予算、年度記録、一軍/二軍の実測、archive参照の保持を比較する。保存再開だけで金額・所属を変更しない。
- 先発不足・進行失敗・未処理例外を成功に数えない。失敗時はtraceと最小再現から原因を特定し、製品修正にはRED→GREENの回帰を付ける。
- 新規/5分類/9機能、価格/投資、契約/FA/取引/スカウト、保存障害/復旧/競合の既存CIとの対応を記録する。

## 範囲と限界

ゲームルール・CPU補強方針・保存形式の再設計、完全バックアップ/復元は含めない。実iPhoneのタッチ/速度、実複数年の耐久、全seedのバランスは別途。QA-04Bの全画面実機受入と混同しない。ブロッカーがあれば事実と残課題を明記し、完了扱いにしない。

## 実進行で確認した修正

100試合まとめ進行の全球団スコア要約を、上限120試合の詳細ボックススコア配列から最後に生成していたため、6試合/日の直近20日しか残らなかった。勝敗累積は100試合でも球団詳細の日程には前半の結果が存在しない。軽量スコアを各試合終了時に別の既存patch形式へ追加し、1回のまとめ処理で転送する詳細120試合の上限は維持する。シミュレーション・乱数・収支・保存スキーマは変更しない。既に欠落した旧結果は勝敗から推測復元しない。

検証結果：関連単体6件、通常CI外8spec/20件、新規143試合旅程のChromium/WebKit2件がローカルで成功。独立レビューの受入不足2件を補強した。最終headのCI・未検証範囲は[検証記録](../validation/qa-04a/README.md)と[PR #502](https://github.com/shotaro-hue/baseball-manager/pull/502)を参照。
