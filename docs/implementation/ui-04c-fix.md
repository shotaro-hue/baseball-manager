# UI-04C-FIX 契約・補強一覧

基準main: `698dafef6ec6a352a754bcc464800588694f292d`（#486）。本書は2026-10-20の実装指示を具体化する。

目的はスマートフォンで候補を探し、選んだ選手の情報だけを読み、明示確認して判断すること。保存形式・年俸/金銭計算・CPU評価・既存の確認/二重実行防止は変更しない。

## 設計

- 共通一覧は名前/年俸、所属・ポジション・年齢・状態の2段。成績と能力計算、全行の比較ボタンは詳細へ移す。長名は自然に折り返し、44px以上の操作領域を保つ。
- 契約の初期表示は要対応（更改対象かつ回答待ちでない）。回答待ち・当年契約済み・全所属を切替。人数は同一の読取モデルで集計。所属/ポジション/年俸/満了までの年数で検索・ソートする。集計詳細は開くまで描画しない。
- トレードは球団→放出側/獲得側の切替一覧→選択サマリー/選択済み比較→金銭→既存確認。両球団の全詳細を同時生成せず、既存取引関数が対応している一軍/二軍/育成を一覧の対象とする。CPUの逆提案候補と評価は元のまま。
- スカウトは報告済み候補と派遣先を切替。候補の検索・絞込・ソートと詳細からの契約/削除を共通化。派遣・報告生成の既存処理を維持。
- FAは既存の国内/代理人交渉・比較・条件確認を維持し、行の成績と比較ボタンのみ詳細へ移す。既存の保存済みビューと復帰処理を利用。
- モバイル詳細中は一覧行をアンマウントし、一覧の条件は親に保持。戻ると安定IDで行を探してフォーカスと位置を復元。退団/削除時は隣接行/検索欄へ復帰。通知の存在しないIDは明示的な対象外表示にし、前の選手を流用しない。
- ページ縦スクロールを使い、一覧内の高さ制限/縦スクロールを除去。スクロールイベントでReact stateを更新しない。仮想化とページ分割は軽量化後の実測を判断根拠とする。

## 検証

同じ固定負荷データ（所属70人/球団、報告120人、市場240人）、同じproduction build設定、Chromium・CPU4倍スロットルでDOM数/表示・選択応答/フレーム/Long Task/GC後heap/一覧復帰位置を比較。390pxは3試行、360/760/761/1023/1024/1440pxは各1試行。Performance traceを保存する。ブラウザの自動計測を実iPhoneの滑らかさ保証に読み替えない。

回帰は状態集計、検索/ソート、通知の退団ID、条件/位置復帰、候補入替、下書き、比較、確認取消、二重実行、予算・所属・保存維持。360/390/1440pxの一覧/詳細画像と境界の横はみ出し/二重スクロールを記録する。
