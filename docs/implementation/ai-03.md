# AI-03 CPU編成循環・ドラフト枠最適化

基準main: `270edd8286762c1de5949953e1887bdb286e36ee` (#479 merged)。2026-10-18。

## 原因と実装

1. 若手の同役割比較対象がないと、将来性基準が0になっていた。CPUは実在する同役割の現在水準と絶対水準60へfallbackする。既存の通常10点・67人超20点差を維持し、自球団の手動/委任時の既存条件は変えない。
2. 満了選手を基本的に全員交渉し、球団による新人との入替判断がなかった。`planCpuRenewals`が契約更改前に、実際の新人候補の球団別観測値と既存戦力を比較する。実打線・両DH打線・ローテーション、能力上位と実測一軍使用、捕手6人・二つの稼働組織、若手の将来性、契約継続中の選手を保護する。満了し、残る層が成立し、実指名基準も通る別々の新人がいる場合に限り放出を計画する。後続の比較には予定新人も受諾済みとして投影する。年齢や人数だけの削減はしない。
3. FAの例外が新人予約を縮小しても、失う新人の価値を比較していなかった。市場開始前に実指名可能な新人を逐次投影し、同役割の代替候補を同時指名枠へ重複計上しない。実受諾・拒否・確定未反映も重ねない。予約消費がある例外獲得は、現在能力または若手の現在/将来合成価値を失う候補と比較する。予算留保は実候補の契約年俸と受諾済み契約に基づく。契約更改は既存の要求額・交渉式を使用する。

実候補の生成をCPU更改前へ前倒しし、既存`offseasonPlan`に候補・観測・計画版を保存する。同じ候補を市場・ドラフト・保存再開で再利用する。旧保存の計画なしは従来どおり市場終了時に生成する。UIの操作・画面構成・初期65人/投32野33・70人上限・成長/成績/給与の式は変更していない。生成時期と交渉対象の差により乱数順は変わる。

## 理由の記録

`cpuDecisionTrace.js`の任意購読で更改計画、各選手の継続/放出理由、実交渉結果・金額、市場予約と獲得、指名/終了、前後人数、新人契約年俸を記録する。通常プレイは詳細ログを保持せず、検証ハーネスがJSONLと年度JSONを保存する。加入/退団の既存球歴は維持する。新人の入団時には既存仕様どおり即時の予算引落しは行わず、`committedRookiePayroll`と`immediateSpending:0`を区別する。

## 回帰と独立レビュー

65/67/69/70、弱い/有力な候補、若手・ベテラン・高年俸・継続契約、捕手・位置保護、実DH、一つの候補を複数放出へ流用しないこと、新人枠とFAの比較、実受諾/拒否/確定、旧保存、複数年度の更改/保存を検査する。既存の育成両フラグ・昇格・70上限の回帰は維持する。

独立レビュー`1a0fccd`で3件のImportantを再現した: 放出理由に用いた新人が実指名では不適格、同役割の代替候補が同時予約になる、同じ主位置の1BとDHの実レギュラーを保護しない。各RED→GREENで、実指名評価の共通化、仮受諾の逐次投影、実起用ID保護を追加した。重複所属時のNaN留保による負予算も財務上Importantへ格上げし、無効な所属の更改は入力を保持して停止する。テスト削除・skip・assert緩和なし。肯定ケースの観測85/90は既存20点例外を実際に満たす入力へ修正し、不適格55/65の否定ケースを別途追加した。

## 検証状況

- 開始時48テスト成功。修正後の対象テスト・実ブラウザ旅程は実行ログを保持する。
- 最初のブラウザ旅程は、独立画面にないhub保存ボタンを待って120秒で失敗した。市場終了の実自動保存を観測する正しい経路へ修正し、再実行のexit0とPlaywright `status:passed`を確認。stdoutの末尾欠落は合格行を生成せず、そのまま残す。
- 初期実装`668afeb`の校正1seed×3年は完走。70人は初年度0/11、3年計0/33。最終製品の10年受入とは区別する。
- ローカルの全体fast試験と改善前長期の並行負荷でメモリ不足が発生。fastはexit1、改善前はseed15の7年/seed16途中で中断(exit130)。これらは合格に含めない。原本は[検証記録](../validation/ai-03/README.md)に保持する。
- 最終の比較は、同じNode24・同じ診断ハーネス・1worker/2300MB・143試合・12球団・実二軍・実更改/市場/ドラフト・実保存再開を、独立した6ジョブで実行する。固定ソースtar、SHA-256、年度原本、Vitest JSONと実終了コードを保存する。標準CIも正確な提出headで成功が必要。

## 判断と制限

**受入・マージ判断は長期比較と最終CIの完了後に確定する。現時点では未完了。**

候補は計画上の獲得可能な代替であり指名確約ではない。球団間ではドラフト順に別々の候補を想定し、実会議での競合は維持する。ポストシーズン大会・優勝収入は比較両側で迂回し、完全App10年とは主張しない。最終年の翌年出場、CPU全員の全球歴DB再読込、実機Safariは対象外。既存の育成片側フラグの更改年俸/在籍年数処理は変更しない。
