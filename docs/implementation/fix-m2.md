# FIX-M2 — 試合前需要による収入計上と赤字予算の整合

作成: 2026-10-19。基準main: `99b73a3a2d3b64735fa5edbd807dfab1fe9d0c42`（#483マージ済み）。UI-04Bより前の独立修正。本PRは未マージ。

## 目的と確定方針

- **収入計上の時点**: チケット価格・球場レベル・人気・勝率は試合開始前に確定している値を使用。当該試合の結果による人気/勝率変化は次の試合の需要にのみ反映する。
- **主催区分**: 主催球団のみチケット/飲食/物販の収入と興行費を計上。双方とも年間スポンサー/放映権/会員と固定費の日割り配賦を受ける。勝敗視点と開催地は別の引数のまま維持。
- **共通処理**: `applyRegularSeasonTeamUpdate`で純粋な`applyClubGameFinance`を試合前のteamに対して計算し、勝敗・人気・選手状態更新後のteamにレジャー/予算/売上だけを転記。通常戦・単日/まとめWorker・CPUの既存呼び出しをすべて共有し、別ルールを作らない。
- **負予算**: `budget`は編成予算残枠であり現金残高/借入金ではない。運営費による赤字（負値）は不正データではないため、保存・試合進行・翌年度更新で勝手にゼロへ丸めない。追加の金銭支出は予算が不足する場合に拒否するが、赤字の現状維持または赤字縮小となる無金銭/受取トレードを不当に拒否しない。
- **年度配分**: 既存`nextClubBudget`の規定最小配分と契約年俸控除を維持。赤字を翌年へ現金借入として繰り越す会計は本工程で導入しない。
- **旧セーブ**: `clubFinance`未導入年度の既存`calcRevenue`処理を変更しない。新しい保存フィールド/移行処理は不要。

## 修正対象

1. `src/engine/regularGameUpdates.js`: 試合前に現行の共通レジャーを計上し、試合後の勝敗/人気に需要が引っ張られないようにする。
2. `src/engine/tradeTransaction.js`: 金銭差引後の予算が非負になることの一律必須条件を、赤字を深めない判定へ限定変更。元の予算が非負なら負値へ跨ぐ出金は禁止する。
3. 単体/結合テスト: 実ホームと視点、手動価格500/5000円と自動価格、同じroundの二重計上、Worker、赤字進行・トレード、旧セーブ分岐を検証。
4. `ROADMAP.md` / `ui-04.md` / `TEST_STRATEGY.md`: M2の状態とUI-04Bへの依存を正しく記録する。

## リスク・対象外

- 人気/成績の変化を受ける需要の「計上順」を修正するもので、球団別動員、価格弾力性、商業契約、給与の定数は変更しない。実在NPB各球団の決算と同一になるものではない。
- `nextClubBudget`、給与支払時期、現金会計、融資、CPU補強戦略そのもの、全画面UI刷新は変更しない。
- 赤字下のトレードを許容する場合も、支配下上限・所有権・選手ID重複・金額の有限性・確定済み取引整合性は既存の検証を残す。
