## レビュー対象と判定

対象は#475のbase `b0eaa58b02149af2e77073c3de495a14aa2b9779`からhead `0839fb0f337c999092cccf2b60460ca628cce9d8`までの差分。マージ後mainとPR headのtreeは一致する。初期生成、FULL編成、補強需要、確定指名、FA画面の人数説明、保存互換、回帰試験を読み、独立した担当にもコードレビューを依頼した。

**P2の回帰を1件検出したため、限定した補足修正を行う。** 通常一軍3人・最低2人・支配下主捕手6人の目安という方針は維持する。健康な捕手適性選手が球団全体で3人のときの一軍2人＋二軍1人はFULL編成での非常時対応であり、通常人数を2人へ変更するものではない。健康2人以下では一軍を優先し、二軍成立は保証できない。

## 検出した回帰と補足修正

`src/engine/rosterAutomation.js`の`buildFullRosterPlan()`で、通常の一軍枠充足処理の後に余剰捕手を降格していた。その後の補充がなく、昇格可能な選手が二軍にいても一軍の枠を空けたまま返していた。編成の有効性検証は出場可能性を確認するため、26〜27人でもこの問題を検出できなかった。

- 既存`e2e/fixtures/new-game.json.gz`のteamId=0：一軍28人・捕手4人から一軍27人・捕手3人となる。
- 通常の初期生成：テストと同じLCGのseed=4・teamId=9で一軍26人。seed=20261016・teamId=9でも27人を確認した。
- FULL編成の定期更新は14日間隔なので、捕手3人・二軍捕手ありの有効な編成では、空き枠だけを理由に即時再編成されない。

補足修正は、最後の捕手配置調整後に空きがある有効な編成で、既存`buildRosterRecs()`の昇格処理だけを再利用する。`fillVacanciesOnly`で通常の3段階の枠充足処理までを実行し、二度目の選手入れ替え評価を行わない。既存の投手・野手人数、方針評価、外国人枠、育成・登録待機、二軍の最後の捕手保護を使い、結果を再検証して採用する。候補不足時に28人へ強制充足しない。

保存形式、契約、選手生成数・能力・ID・乱数消費、通常3人／非常時2＋1の方針は変更しない。補充される控え選手が変わるため、初期所属・以後の試合結果まで同じになるとは扱わない。手動・緊急モードへの新しい日次編成も追加しない。

この増加はドラフト区間で発生している。6人充足時には`rankDraftProspects()`の捕手不足加点は停止するが、野手共通加点・若手加点・選手評価による選択は残る。どの点数が各指名を決めたかは既存の人数観測からは確定できず、11人という人数だけで不当な指名や#475による新規回帰と断定しない。
