# UI-03D: 成長レポートの一覧・個別内訳

基準main: `fd818af6701e9ce833d105928065a9235ad39a50`（#466マージ）。添付ZIPは実装基準にしない。
2026-10-14にユーザーが[成長レポートのモック](../validation/ui-03d/approved-mock.png)と情報整理方針を承認し、要件確定・実装を依頼。本ブランチは未マージ。

## 確定した要件

目的は、全選手の能力表と説明文を順に読む負担を減らし、「誰にどんな変化が記録されているか」を見渡して必要な選手だけ詳しく読むこと。

| 項目 | 受け入れ条件 |
|---|---|
| 概要 | 急成長／成長／下降の既存記録人数。記録対象の一軍登録選手を明記し、全所属選手の集計と混同しない |
| 一覧 | 選手名・役割・年齢・区分、比較できる主な変化を絶対差の大きい順に最大2項目、保存された合計変化量を表示 |
| 絞り込み | 記録／上昇（急成長＋成長）／下降。表示だけを変える。空の記録と未記録を区別し、他区分の欠測で記録済みの0件を未記録扱いにしない |
| 個別内訳 | 選んだ1人だけ「能力・前・現在・差」の表と既存選手詳細／年度別成績への入口を表示 |
| 戻る | スマホは一覧と内訳を切り替え、一覧の絞り込み・選手行の画面内位置・フォーカスを復帰。PCは十分な表示領域がある場合に並置し、狭い埋め込み領域は切り替え。別の絞り込みでは古い内訳を閉じる |
| 補足 | 同じ説明を選手ごとに繰り返さず、共通の「表示の見方」へまとめる。下降は放出の推奨ではないことを表示 |
| 異常状態 | 0・未記録、空、部分記録、選手情報なし、現在値なし、長い名前を区別。記録が消えた／save ID・球団・年度が変わった際は選択を破棄 |
| 既存経路 | 編成内の「編成に戻る」は親の開閉領域だけを閉じる。独立画面の次工程・処理ロック・失敗再試行を維持 |
| デザイン | DES-01のネイビー・白・青、写真なし。44px操作、表内だけの横スクロール、360／390pxとPC・境界幅で確認 |

対象は `GrowthSummaryScreen` とその埋め込み開閉接続。契約更改、FA市場、引退、戦力外、経営の内部画面は対象外。
成長計算・区分の判定・乱数・保存形式・保存キュー・ゲーム進行は変更しない。新しいUI状態をセーブへ追加しない。

## データの意味

既存 `summary.breakout/growth/decline` の記録と `item.diff` を表示する。区分・合計をUIで再査定しない。
個別の「前」は記録に含まれる選手スナップショット。「現在」はID一致の球団一軍・二軍・FA市場から取得する。ID 0を除外しない。
双方が有限値の項目だけ差を表示し、片側がなければ未記録。合計変化量を現在値から再計算しない。
一覧の2項目は全内訳ではない。士気等の更改変更を成長合計へ加えない。未記録の二軍内訳や小さな変化は生成しない。
33歳以上・記録された下降5pt以上の既存警告基準は維持する。自動放出や放出推奨へ変えない。

一覧からの絞り込み・選択・復帰と、異なる記録へ移った際の選択破棄は一時的なUI状態として保持する。

関連Unit: `npx vitest run src/components/growthReport.test.js src/components/offseasonReview.test.js src/components/offseasonPlanning.test.js`。

## PR #467 レビュー指摘の修正（2026-10-14）

- **編成内のPC表示**：画面幅だけで2列にしていたため、実Appの編成補足欄で一覧幅が139px（1024px画面）／211px（1440px画面）となり、225pxの固定名前列が変化量を覆った。レポート自身を名前付きコンテナとし、PCでも内容幅720px以上の時だけ並置する。狭い領域は選んだ1人の内訳へ切り替え、戻れば一覧を表示する。修正後の内訳幅は310px／454pxで、必要な値は表内の横スクロールで確認できる。
- **PCの連続選択からの復帰**：1人を開いた後、スクロールした一覧内で別の選手を選ぶと、戻る際に一覧の内部スクロールがなくなる。単に保存したscrollTopを戻してもフォーカス先が画面外へ移動した。選択時の選手行の画面内位置を記録し、復帰後のレイアウト差をwindowスクロールへ反映する。保存データにUI状態を追加しない。
- **回帰の確認**：修正前の1440pxで、実Appの変化量セルが固定列に覆われるテストと、28行の最後を連続選択して戻った際にフォーカス行が画面外へ残るテストの2件が失敗（RED）。修正後は成功（GREEN）。実Appの1024pxを追加し、表示中の合計・比較セルが他の列に覆われず読めることを実ブラウザのヒット判定で確認。連続選択は1024／1440pxで検証する。
- **最終ローカル検証**：関連Unit43件、対象Chromium E2E13件成功。既存の7幅・異常状態・実App360／390／1024／1440pxの開閉・詳細・保存再開を含む。テスト削除・skip・期待の弱体化なし。追加の独立レビューで重要指摘なし（コンテナ境界719／720pxと、選択後の幅変更からの復帰も確認）。
- **追加WebKit確認の限界**：実App390／1440pxと連続選択1440pxの3ケースを実行しようとしたが、この環境にWebKit実行ファイルがなく、画面を起動できなかった。製品動作の成功／失敗とは扱わず、上記Safari/WebKit未検証を維持する。通常CI設定は変更しない。

同じdraw-complete保存fixtureの同じ選手にミート+3・長打+2の記録を設定して比較。1440×900の修正前・修正後は同じ選手・成長記録・編成画面・内訳選択で、修正前は隠れた合計列を右端までスクロールしても読めない状態。1024×900も同じ入力で修正後を確認。いずれもローカルChromiumのviewport画像。
