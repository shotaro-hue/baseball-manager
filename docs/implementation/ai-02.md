# AI-02 — CPUドラフトの投手役割別補強判断

基準main: `1e607e753b09bb87da16a626f6de33377ac0f82b`。#444/#445/#447の確定指名・組織評価を維持する。対象は投手候補の補強加点と、指名情報を評価へ渡す経路のみ。FA、更改、戦力外、昇降格、推薦／展望、保存スキーマは変更しない。

## 原因と変更

旧 `chooseDraftProspect` は `wantsPitcher` を全投手に適用する。先発のみ不足でも、同能力で先に並ぶ中継ぎを優先した。二軍・指名者の人数を単純に加算していたため、負傷・登録待機・育成しかいない層の稼働不足も区別できなかった。

- 読み取り専用 `evaluateOrganizationNeeds` を再利用し、実際のteamを評価する。役割は既存のsubtype（先発／中継ぎ／抑え）。既存最低人数（4／3／1）、先発若手24歳以下2人・主力年齢30歳以下3人を使い、新しい人数基準は設けない。
- 役割の組織不足がある場合、その役割の候補へ従来26／24点。先発将来層のみ不足なら該当年齢層の先発候補へ同点。組織不足は能力・年齢の上限を意味しない。
- 組織所有は充足するが、`activeShortage - availableFarmCount - acceptedPickCount` が正の部分は13／12点。所有層の一時的な利用不能は、新規獲得の必要性として組織全体の人数不足より弱いため半分に抑える。指名者を稼働人数へ足すのではなく、後続ドラフトで既に計画済みの役割を過剰加点しないための減算である。
- 健康・支配下・登録待機なしの二軍候補は現在の直接昇格枠がなくても組織深度に含める。`directlyPromotableFarmCount` が0で `availableFarmCount` がある（28枠・外国人制約等）状態は、入替が必要な所属戦力として扱い、ドラフトへ自動的に再加点しない。資格は能力的な即戦力の保証ではなく、主力入替の可否や能力比較を本工程は変更しない。
- `classification`／`reasons` の意味はAI-01のまま。組織不足を最大加点、利用可能なfarm・確定指名により充足する部分を0、利用不能な層のみを半分として、個別不足数を優先する（複数課題が併記されるため分類ラベルだけで排他的に判断しない）。
- 一軍の球威不足は全投手に関わる能力ニーズとして残す。役割・将来・球威の加点は加算せず最大26／24点。候補順の100−i×3／2、即戦力度×0.2／潜在能力×0.15、既存若手・ミート・捕手加点、乱数分岐はそのまま。強い候補の順位／能力差で不足役割が選ばれない場合もある。

## 確定指名の入口

`chooseDraftProspect(team,pool,round,acceptedPicks,draftContext)` の第4引数配列を維持し、未所属確定指名を既存 `draftPool`／`drafted` へ投影する小さなアダプタを設ける。正式入団させたり一軍へ追加したりしない。

実 `DraftScreen` は既存配列に加えて第5引数へ本物の `{teams,draftPool:pool,drafted}` を渡す。このcanonical情報を優先し、評価結果のaccepted IDのみを旧捕手・年齢・能力ニーズへの投影に使う。拒否、他球団、1巡目／後続巡の競合、null ID、所属済み（他球団も含む）、重複をAI-01の既存処理で除外し、ID 0は保持する。1巡目の手動／全自動もleagueを渡す。新規保存フィールドはなし。

所属IDが不正で評価 `ok:false` なら、役割人数を捏造せず従来の加点にfallbackする。既存不正ロスターを修復する機能ではない。入団成立・予約枠・抽選・拒否・全自動処理のガードは変更しない。
