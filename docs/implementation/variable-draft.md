## 原因と変更

従来は全6巡の候補順位から必ず選び、充足した役割へ追加する価値の判定がなかった。捕手不足加点を停止しても、野手共通fitと観測評価で捕手が上位なら繰り返し指名していた。

新しく作る会議だけ160候補（投手80＝32先発/27中継ぎ/21抑え、野手80）＋既存スカウト候補、年間最大10人とする。各球団は1位入札前を含む任意の指名前に選択終了できる。確認に当年再参加不可を示し、確定済みの指名は保持する。全自動でも終了を解除しない。

`draftConference.js`がルールと参加資格を、`draftContinuation.js`がCPUの継続理由を導く。順位の重み、観測・調査、抽選、指名順、拒否確率、財務式は維持する。CPU候補は不足補充、現在能力の更新、若手将来層の更新のいずれかを説明できるものに絞り、その中から既存順位で選ぶ。捕手6人を保有上限にしない。

充足時の更新差は既存評価帯1段階の10点を初期校正値とした。現在能力は既存の稼働最低人数分の末尾、将来性は同役割の24歳以下の最大値と比較する。確定新人は当球団の観測レポートを使う。公開予想は公開レポートのみを使い、私有レポートや未発表の結果へ依存しない。長期最適値の実証ではない。

## 保存互換と境界

- ルール版なしの会議は6巡、既存候補・手番・当選・調査ポイントのまま。ロードで候補を作り直さない。次に作る会議から版2／10人へ移る。
- 終了球団と理由を既存のlottery/draft viewへ追加保存し、画面遷移時に引き継ぐ。年間指名数は保存済みの1位結果と指名logから導出し、派生人数を重複保存しない。
- 拒否は年間指名1人・入団予約0人。抽選落選は0人。ID0を有効に扱う。結果反映時にも年間10人とR＋Pの70人を再検証する。
- 旧保存の拒否済み1位を受諾一覧へ混ぜないようにした。年間指名ではその1位を保持する。所属・球歴・既存保存スキーマの強制移行はない。
- 既存テストの同一所有IDを二球団へ複製したfixtureを、二球団で一意のIDへ修正した。期待する指名・入力不変のassertは維持。共通人数の所有競合を隠すための緩和ではない。
