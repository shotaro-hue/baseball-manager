# UI-04D — 通知・記録・OB・設定の本文移行

2026-10-24。ユーザーは#500レビュー後の候補③を指定し、UI-04D着手を選択。既存[UI-04](ui-04.md)と[DES-01](../DESIGN_SYSTEM.md)を継承する。QA-04A全体の先行実施は今回の前提から外すが、対象画面の回帰検証は実施する。

## 目的と範囲
スマホで対応する通知を探し、1件を読んで判断し、元の一覧へ戻れること。過去の記録・退団選手を読みやすくし、設定から実在する操作へ迷わず移れること。

- 受信箱: 未読／既読と要対応／対応済みを分離。既読化だけでは取引を確定しない。既存確認・拒否・失敗・外部取引後の更新を維持。
- ニュース: 回答待ち／回答済みは保存済みansweredのみから表示。新しい一般ニュース既読状態を作らない。インタビュー確定と移籍金の意味は既存のまま。
- 記録: 最新表彰／歴代タイトル／通算／年度別順位／殿堂を維持。年度選択で長い履歴を絞り、旧年度の集計を再計算しない。
- OB: 既存退団履歴、在籍年数、退団理由、選択後のCareerTableを維持。
- 設定: 実在するホームの進行操作・編成の起用設定へ案内し、開発者向けバランス検証は分離する。架空の保存・音量・通知設定を増やさない。

## 構成と実装判断
既存画面へのCSS上書きのみでは、div操作・一覧全件描画・スマホ横並びが残るため採用しない。全画面の新規ルーティングや保存UI状態は不要。既存props/handler/tab IDを維持し、対象だけのDES-01 CSSと軽量一覧を共用する。

通知・OBはPCで一覧＋選択詳細、760px以下で一覧または詳細。選択はnative button、戻る際は一覧位置・選択行へフォーカス復帰。一覧は40件ずつ表示して本文・CareerTableは選択中だけ描画。検索や分類は一時UI状態。記録は選択年度のみ描画する。

## 受入
360/390/760/761/1023/1024/1440pxで本文の横はみ出しなし、44px操作、本文16px・一覧14px。Chromium/WebKitで選択・戻る・状態更新・画面往復・保存再開を確認。閲覧・絞込で所属・予算・記録を書き換えず、確認取消や失敗を成功表示しない。同一fixtureの変更前後PNGを残す。

## 対象外
ゲーム/CPU/財務/保存形式・完全バックアップ・ニュース既読スキーマ・全画面CSS再編・実機iPhoneの滑らかさ認定。マージしない。
