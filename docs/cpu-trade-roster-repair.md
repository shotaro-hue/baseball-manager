# CPUトレード後の先発編成エラー

## 再現と原因

PR404の経済検証と同じ条件（seed 20260911）を修正前のmainで再実行すると、2027年のまとめてシムが「DHなしの先発に出場不可選手が含まれています」で停止した。

失敗時の阪神は52勝26敗。DHあり・なしの先発に `qq08mfa` が残っていたが、一軍・ファームの両方に存在しなかった。直前のCPUトレードは阪神と巨人の間で成立し、このIDの野手を阪神が放出していた。

まとめてシムの処理順は「朝の編成整備→CPU試合→CPUトレード→自チームの試合」。自チームの相手球団が朝の整備後に選手を失っても、所属だけが交換され、打順・守備・ローテが更新されなかった。出場不可の検証自体は正しく、検証を回避する修正は不要。

## 修正

- まとめてシムのCPUトレードは、その日のすべての公式戦が終わった後に実行する。当日に移籍した選手が別球団で再び試合に出る経路も防ぐ。
- CPUトレードの実行を共有部品にまとめ、まとめてシム・1試合ワーカー・従来の試合処理で使用する。
- 両球団の一軍・ファームから放出選手を除き、獲得選手を追加してCPUの通常の編成方針で再編成する。DHあり・なし、守備位置、先発ローテ、登録人数・外国人枠を検証する。
- 移籍元がファームでも旧球団のファームに残さない。所属が変わった後の同じ交換要求は再実行しない。
- 両球団の編成が成立しない場合は交換を確定せず、移籍ニュースも出さない。既存の球団オブジェクトを更新し、確定前までに記録した試合成績・勝敗・収入を保持する。

ユーザーの手動編成・ユーザートレード、投手交代、物理演算、給与係数、FA宣言率には変更を加えていない。トレードのタイミングが変わるため、同じ乱数seedでも以後の試合結果や宣言人数は修正前と一致しない。

## 検証

- 元の失敗条件は修正前に再現し、直前の交換選手IDと先発の欠損IDが一致することを確認した。
- 同じseedで2026〜2028年を完走し、各年12球団の143試合完了を確認した。経済検証はPR404のハーネスを一時的に使用し、診断用スナップショットやハーネスの複製はコミットしない。
- 小さな回帰テストで、先発野手の交換、ファーム選手の移籍、投手ローテの更新、二重処理防止、自チーム試合後の交換と翌日の継続を検証する。
- 本番ビルドと通常テスト一式を実行する。スマホ目視・ブラウザE2Eは未実施。

PR404の記録は当時の失敗結果として保持する。この修正は上記の条件で見つかったCPUトレードの原因を扱い、すべての編成エラーや完全な長期経済を保証するものではない。
