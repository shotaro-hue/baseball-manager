# 分析UI改善 第2弾 要件・設計

## 目的

「数字を探す」「リーグ内で評価する」「2選手を比較する」「起用・編成判断へ進む」を一続きの操作にする。

## 実装範囲

1. 成績一覧の全列3段階ソート
2. 打球分析のリーグ順位・上位率・リーグ平均
3. 最大2選手の比較トレイ
4. ホーム画面の固定モック廃止と実データ化
5. 他球団詳細の自球団比較
6. 選手詳細からロスター・契約・トレードへの判断導線

## データ方針

- 生打球はIndexedDBの保存済みイベントを期間条件ごとに集計する。
- 比較母集団は初期値を同一リーグとし、同一の期間・結果条件を適用する。
- 比較用集計は画面表示時に一括取得し、ゲーム中のメモリ保持分へフォールバックできる。
- 10打球未満は順位非表示、10〜29打球は参考順位、30打球以上は正式順位とする。
- 過去履歴がない既存セーブは復元せず、保存開始以降またはメモリ保持範囲であることを明示する。

## UI方針

- ソート状態は列見出しの矢印と補助文で明示する。
- モバイルでは選手名を固定し、比較トレイは画面下部に表示する。
- 順位は数値だけでなく母集団、上位率、リーグ平均、対象打球数とセットで表示する。
- 平均打球角度など高いほど良いと言えない指標は順位化しない。
- 他球団比較は根拠不明の総合点を使わず、OPS、得点、ERA、守備、年俸、予算を直接比較する。

## 受入基準

- 列見出しを3回押すと降順、昇順、初期順へ戻る。
- 投球回は表示文字列ではなくアウト数相当で比較する。
- 欠損値は昇降順に関係なく末尾へ置く。
- 打球フィルタ変更時、N数・指標・チャート・比較順位が同時に更新される。
- 小標本選手が正式なリーグ1位として表示されない。
- 比較トレイは3人目を追加せず、セーブデータにも保存しない。
- ホームの注意項目は実データ変更に追随する。
- 他球団の比較ボタンで比較パネルが表示・非表示になる。
- 選手詳細から遷移後も対象選手名が判断コンテキストとして残る。
