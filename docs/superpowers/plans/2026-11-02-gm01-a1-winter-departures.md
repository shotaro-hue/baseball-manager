# GM-01 A1-2c-1 冬の退団・自由契約市場の共通処理

## 目的と範囲

#535マージ後のmain `bf4651a9ac9730b56b006623385d96c1ce699c5d` から開始。
[親計画Task 7](./2026-10-30-gm01-a1-integration.md)と[設計5.1](../specs/2026-10-30-gm01-a1-integration-design.md)に従う。
A1-2cは、冬の共通処理と、期中の試合成立判定・FA資格/補償・海外/収入・人の操作接続を分割する。
本PRでは前者を実装し、Task 7全体や一般公開を完了扱いにしない。

## 受入条件

- v2 `enter-market {id,teamId,playerId,contractId,reason:'expiry'|'release'}` は冬だけ許可する。ID 0も有効。
- 満了は自然満了のまま。継続契約の解雇は翌2/1 `end/release/retain`。未知保証も残額を留保し、過年度費用・旧条件を変更しない。
- `offseasonDepartures`に元契約・元年俸・選手snapshot・通知日・効力日・台帳action・receiptを記録する。正当な同年退団だけ11/30の雇用照合から除外する。
- 未回答のエンジン更改留保は取消履歴を残す。未更改計画は証跡を維持して見積から除外し、空いた枠の最低維持費を復活させる。受諾済み将来契約は勝手に取消さず退団を拒否する。
- 名簿・配置参照・退団履歴・明示的なreleased市場・契約・receiptを一括candidateにする。正規の市場契約へ渡せること。返金・FA補償・他の市場への推定転送をしない。
- quote/rejectは非変更。replayは参照同一。保存・再読込で履歴を保全し、孤立記録/改変receipt/未証明未来actionは拒否。
- schema/DB version/公開ゲート/旧モード/UIを変更しない。期中commandはplayability未接続のため拒否。

## 実装順

1. 冬の満了/継続保証解雇、名簿照合、改変拒否、留保と計画額のテストをREDにする。
2. `annualDepartures`を既存のtransaction/worldへ接続し、`renewalPlans`の証跡を保つ。spending内の退団情報は検証済みengineから毎回作る投影のみ。重複保存を拒否する。
3. 旧保証不明・既存市場受諾・小/大root保存失敗と再読込の回帰を追加し、関連回帰/ビルドを確認する。
4. 独立レビューと最新HEAD必須CIを確認して新規PRを提示し、未マージで止める。

## Review Focus

- 同年冬以外のdepartureで名簿照合を迂回しないか。source contract/receipt/actionの欠落・改変を検知できるか。
- 未来の保証負担と過年度行を維持するか。旧保証不明や未記録の署名条件を推定していないか。
- 未更改計画と正式留保の解除が過大な余力を作らないか。再読込時も同じ投影か。
- 既存FA取得が旧雇用と衝突しないか。UI/人のdecision/CPU/年度更新まで完了したと誤表示しないか。
