# F3-B 通算履歴確定 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans; independent review before publication.

**Goal:** 年度本体と通算履歴を同じ確定世代へ結び付け、異なるゲームの履歴を混ぜない。
**Architecture:** version 6 manifest adds one immutable careerLogs chunk. Version 5's four references remain readable and reusable with their original row format. New games seed only their own supplied history; existing games migrate legacy playerId rows read-only. Career patches travel with a save request and clear only after successful commit.
**Tech Stack:** existing JS, Vitest/fake-indexeddb, React hooks, Playwright.
**Spec:** docs/f3-b-save-integrity-design.md and user F3 v2 B01–B04.

## Global Constraints
- Preserve main 9efaf56 / #420–#428 and F3-A; no main push or merge.

- Batted-ball archive remains independently committed; report this boundary.

## Review Focus
- First-game failure with colliding playerId preserves old career history.
- Career chunk missing rejects the whole new-format candidate.
- Failed/queued requests retain career patches; successful older request cannot erase later patches.
- Backup restores that generation's full career history, including retired and FA players.
- Legacy migration read/write failure must preserve original game and fixed rows.
