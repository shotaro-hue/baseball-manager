# FIX-R1 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make batch save status and batting highlights agree with actual persistence and match history.

**Architecture:** Route batch saves through the existing tracked `handleSave` path with the adopted state/history payload. Publish only the latest request in the current progress session, keeping dirty-version and queue semantics. Resolve highlights lazily from the current batch's game numbers and history map, guarded by transient save/year/team/session context.

**Tech Stack:** React, Vitest/react-test-renderer, Playwright, existing IndexedDB/save queue.

**Spec:** User FIX-R1 request; existing `docs/implementation/ui-01d.md`.

## Global Constraints

- No main push, merge or auto-merge; one independent PR.
- Keep Worker, game/stat calculations, save format and unrelated UI unchanged.
- Preserve failed results, home retry, deferred highlights and 8-row pagination.
- Use targeted local tests, full unit/build/core browser CI on the final commit.

## Review Focus

- Archive flush may finish after a newer batch/save or a load: older notifications must not replace current state.
- A successful older snapshot must not clear newer edits or dirty scopes.
- Shared queued saves must still coalesce/persist their latest snapshot once.
- Same game number after a year/load change must not resolve stale batch details.
- Null/malformed entries, ID zero, and duplicate names must not fabricate counts or break navigation.
