# GM-01 明示日付を持つpostseason producer

## 目的と今回の範囲

親目標は通常プレイの閉幕から12/1の引退・posting、翌春まで保存を保って進めること。#557後のmain `bb77dad6`では143試合後のgameDay144は7月のAll-Star格納位置であり、年度時計へ使用できない。今回完成させる依存工程は、通常プレイの最終公式戦→CS→日本シリーズで実日付を生成し、既存の途中保存・再開で保持すること。終了日を照合できる純粋selectorを後続のopen-offseasonに提供する。

## 方針と代替案

- gameDay144を143へ丸める案は、現在日付を最終公式戦日と偽るため採用しない。
- 11/30固定値を後付けする案は、終了した試合の根拠にならないため採用しない。
- 実際に生成された公式143戦目の日付を起点とする、明示したゲーム内カレンダーv1を採用する。実際のNPB発表日程を再現したものとは扱わない。

実装上の選定はAGENTS.mdの「次へ」の委任範囲に基づく。追加の仕様承認を繰り返さず、実装者が担当し、提出前に別コンテキストのレビューを受ける。

## ゲーム内カレンダーv1

最終公式戦の翌日は休養日、その翌日に両リーグCSファースト開始（最大3連戦）。最大日程終了後1休養日を置き両CSファイナル開始。ファイナルは2026年以降の最大7試合、以前は最大6試合を予約し、最大日程終了後1休養日を置き日本シリーズ開始する。早期決着で開始日を変えず、両リーグの逐次シミュレーション順にも依存しない。日本シリーズは既存のホーム順を維持し、第2・5・8戦後に移動日を挟む。7戦までの引分と8戦以降の延長規則は既存処理を維持する（7引分＋最大7決着試合の最大14実試合）。年を越す、または12/1以降になる日程は明示的に拒否し、切り詰めない。

## データ経路・互換性

`generateSeasonSchedule` → `useSeasonFlow.startPlayoff` → `initPlayoff({year,schedule})` → `offseasonPlan.playoff` → 既存save/load。起点は`economyClockFor`の公式戦日付検証を再利用する。新規playoffにpolicy versionと最終公式戦日、seriesに開始日、各gameに実施日を保存する。途中再開時に保存済み日付と元日程の一致を検証し、再抽選・再生成しない。既存の未記録playoffはそのまま再開し、新しい日付や終了根拠を捏造しない。

終了selectorは全seriesの結果を既存ルールで再生検証し、日付・勝ち上がり・日本一の一致を確認して終了日を返す。未完了または旧未記録履歴は終了根拠を返さない。これはnative年度取引のreceiptではなく、後続の終了producerの入力である。現在のannual clock検証は変更せず、無効なgameDay144の拒否も維持する。

## 非対象・完成までの残作業

予算forecast/承認、open-offseason native command、年度成長・要求額、翌春builder、Workerのannual接続、公開判断は対象外。今回の入口は通常のlegacy試合進行だが、annual公開はOFF/schema1/DB5を維持し、年間機能全体の完成とは報告しない。次優先は実収支と予算policyを使った翌年度forecast、および終了根拠とそのforecastを受け取るnative open-offseason。UIの表示・操作は変えない。

## 受入・検証

実日程から開始し、途中JSON/実保存・再開後に同じ次試合日を使用し、日本シリーズ終了日を照合できること。両リーグの早期決着・特殊7戦CS・日本シリーズ引分/追加戦・旧未記録・異常な日付と結果・元日程矛盾を対で確認する。実入口のhookと既存Chromium/WebKitの最終公式戦→postseason保存E2Eを使い、必須CIを最新HEADで確認する。実機iPhone Safariは別工程。
