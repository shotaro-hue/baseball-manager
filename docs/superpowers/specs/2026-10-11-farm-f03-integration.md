# F-03 二軍の実進行接続
main 74010da（PR438取込済み）。合意FIX-F v1.1に沿って実装。

一軍の試合前編成確定後、健康なfarmを専用PRNGで計算する。一軍更新より前にF-02へ全6カードを原子的に適用し、実出場負荷を更新後の同じIDへ適用。試合後の昇格・移籍は当日記録を変更しない。一軍が担当する故障・登録待機tickは増やさない。二軍の新規故障・成長補正は対象外。

負荷の初期モデル：投手BF/2を切上げ、疲労5～40、直近の連投は一軍同様2連投+5/3連投+15。野手PAに応じ疲労1～5。未出場は既存postGame相当の回復（投手recovery能力・野手+6）、condition20～100。球数を捏造せずBFを使う。最終バランスはF-04。

Worker単日・一括と戦術/旧auto callbackへ同じ純粋関数を接続。新規ゲームはsource=new、旧ロードはメモリ上へ明示移行、保存だけで永続化。球宴・プレーオフは進めない。年末runFarmSeasonは全接続から停止し、stats2を書き増やさない。

Reactのcore reducerでteams/gameDay/year/farmCompetitionを同じactionへ採用。taskIdの既存防御に加え、編成変更・ロード/新規開始で変わるprogress tokenを照合し古い完了を拒否。保存payloadと画面採用のcompetitionを一致させる。通常保存失敗は一致した未保存メモリを残し、再保存だけ行う。年度更新はadvanceFarmYearの旧日程/new nextSchedule契約を使用し、archiveと新年候補の保存成功後だけ公開。

編成二軍表・選手詳細に新正本の期間/実施数/由来/主要成績を最小追加し、昇格後も参照可能。旧stats2は旧推定として隔離。旧ランキングと二軍年間表彰は新記録導入後に保留表示とし、F-04の閾値承認前にタイトルを発行しない。全面CSS刷新、CPU補強AI、重点育成は非対象。

検証：3経路、重複・中断・古い完了、故障残1/登録tick、昇降格負荷、143終了/球宴、旧load/backup、保存失敗/再試行、年度更新、主要画面360/390/1440。既存回帰を維持し正確なPR head CIを要求。マージしない。
