# ポスティング希望の年一度の生成と受信箱接続

基準main: `b022485111ae5d447d7c3f7b0f37c3b88e27f102`（#554マージ済み）。
継続依頼とAGENTS.mdに従い、未完成のポスティングを一工程進める。

## プレイヤーの結果と範囲

annualの12月1日、受信箱で「海外挑戦の希望を確認する」を実行すると、
自球団の一軍・二軍の支配下選手から希望を生成し、既存の申請→判断→海外交渉へ接続する。
希望者ゼロも保存し、再開・保存失敗・別取引後に抽選をやり直さない。
承認前に所属・給与・保証・士気・予算を変えない。
CPU判断、年度Workerからの呼出、年度切替、長期校正、一般公開は対象外。
Task7/A1と機能全体は未完成。公開OFF/schemaVersion1/DB5を維持する。

## 方針と代替

- 採用：既存の希望確率（海外志向60以上、年齢・士気・出場量）を、保存root別の
  専用乱数で再現する。市場価格・本人受諾policyは変更しない。
- 読込時の自動更新は採らない。閲覧だけでは取引を生成せず、共通保存で確定する。
- 全年度/CPUをまとめて実装しない。まだ未接続の年度処理を成功扱いしない。

海外志向の欠測は既存市場と同じseed/選手/年度のゲーム推定を共有し、実測0を維持する。
年齢は既存資格の出生日根拠から取得する。PA/BFの欠測はsnapshotにnullで残す。
育成、引退/予約、正式留保、将来契約、既申請・旧postingRequestedは対象外。
判定時点の入力・確率・draw・生成申請IDを親receiptへ保存し、歴史入力から復元検証する。
別候補の順序やcaller IDに乱数を依存させない。球団/年の決定的IDで一回だけ確定する。

## 正本と安全性

createInitialTeams/保存名簿 → native生成command → 既存request-posting →
engine.postingApplications/transactions → commitEconomyOperation → saveGame/採用 →
cold load/受信箱 → 既存decide-posting/run-posting-market。
新しいメールstate、独立保存経路、価格や結果をcallerが指定する入口は作らない。
親子receiptは同時公開。保存失敗は元root/worldを維持し、採用中断は共通復旧を使う。
過年度の能力変化で当時の判定を変更せず、公開済みreceiptのprefixを保護する。
