# GM-01C-2E 市場区分と翌年度獲得契約

基準main: `3a7d57b02452556f19638b8bb95634ca913db764`（PR #511マージ後）。親設計: [GM-01第6節](./2026-10-26-club-management-gameplay-design.md)。ユーザーの本工程の実装PRまで進める指示を実行範囲の根拠とする。既存JavaScript/Vitest、共通quote/apply、契約台帳、年度予算を利用し、本番接続・保存移行は行わない。

## 制度調査：現実、現行ゲーム、今回

一次資料（2026-10-28確認）：

- [NPB FA公式説明（2018年度公示）](https://npb.jp/announcement/2018/fa_about.html)：国内はNPB球団、海外は国内外との契約資格。145日を1季とし国内8季（2007年以降大学/社会人7季）、海外9季、権利再行使は4季。日本シリーズ後の申請・公示を経て翌年度交渉。古い年度の説明であり2026年の規約全文として扱わない。
- [NPB 2026有資格公示](https://npb.jp/announcement/2026/fa_qualified.html)：国内/海外資格を区別して公示。資格取得と宣言は別。
- [選手会公開の野球協約2024/25](https://jpbpa.net/wp-content/uploads/jpbpa-pdf/agc2425.pdf)：第52–53条は契約承認と公示による効力、第64条は8月からシーズン終了翌日までの新規契約制限、第66–69条は70名の保留・保留権・非保留選手の自由契約。年数満了だけで自由交渉可能にはならない。
- [NPB 2025-07-31公式通知](https://npb.jp/news/detail/20250731_01.html)：7月31日で新規契約/譲渡期間終了。育成人数と支配下人数を別集計。
- [日本プロ野球選手会の移籍説明](https://jpbpa.net/transfer/)：国内移籍のA/Bランク補償、Cランク無補償、海外への移籍に国内補償なし。補償改定の可能性は後続の実装時に再確認する。

本ゲームの120日換算、2–11月給与、翌年2月1日の加入/給与統一日は簡略化であり、公示時に効力が発生する現実の協約そのものではない。現行資格式、海外志向、外国人枠、確率・乱数・CPU評価は変更しない。

### mainの市場/契約棚卸し

| 経路 | 現行の役割/問題 | 今回 |
|---|---|---|
| `player.generateForeignFaPool`、`useGameState`初期化、`useOffseason`春更新 | 外国人候補を生成、`isFA=true`。外国人であることと海外FA権を混同できない | 生成元は変更せず、明示入力では自由契約市場として扱う |
| `contract.processCpuContracts`、`useOffseason`更改/宣言/戦力外/育成満了 | 国内宣言と自由契約が同じfaPoolへ。理由や旧所属は任意記録 | 既存履歴から推定・一括変換しない |
| `useOffseason`海外FA/ポスティング | 海外志向と資格でNPB離脱。国内faPool交渉ではない | 独立経路を維持。新規海外球団DB/交渉は対象外 |
| `contract.processCpuFaBids`、`managementDecisions`等 | 人/CPUとも旧budgetから年俸控除し即加入。`offseasonMarket`は旧所属の成績帰属を保護 | 本番は維持。新APIへ全面切替しない |
| `useOffseason`春更新 | 未契約国内市場は成績保存・加齢して持越し、外国人候補は再生成。契約年数は旧投影処理 | 新APIの加入を別途検証。既存更新は変更しない |
| `saveload`、`useGameState`保存 | 旧名簿/faPool/faYears/offseasonPlanを保存。新支出stateは未接続 | 保存形式/移行は変更しない。新stateのJSON往復を検証 |
| `seasonContract`/`contractLedger`/`annualSpending` | 翌年開始契約と全年度留保、競合解放、同年度の遅延効力が存在 | 再利用、給与式は新設しない |
| `annualTransactions` | 同年度即加入FA、更改将来sign、新人の翌春joinが存在 | FA系オフ受諾は将来signを即確定し、春の名簿加入だけ分離 |

A/B人的・金銭補償の実処理は現行コードに見当たらない。SPECの説明を実装済みと読み替えない。宣言機能と資格判定を重複実装せず、新入力は既存資格関数で整合性だけ検査する。

## 方針と代替案

| 案 | 判断 |
|---|---|
| faPool/isFAを全面置換し本番市場も移行 | 旧保存/CPU/画面/Workerの影響が大きく、今回不採用 |
| 市場を別々の契約エンジンへ分割 | 給与/留保/競合/保存の重複となるため不採用 |
| **既存APIへ任意の明示市場情報と加入待ち履歴を追加** | 採用。従来入力を維持し、新しいオフ契約のみ明示情報を必須にする |

この命名と補償対象の受諾を保留する境界は実装担当の判断。小規模な追加モデルで一巡の契約/加入を検証できるため、E-1/2/3の複数PR分割はせず一つの本番未接続PRに限定する。

## データと不変条件

- `player.marketEntry={id,kind,enteredDate,originTeamId?,compensationRank?}`。kindは`domestic-fa`/`overseas-fa`/`released`。FAは旧所属とA/B/C/exemptランクを必須（exemptは外国人のみ）。releasedはランクを持たない。明示FAは既存getFaProgressの資格と支配下区分を検査する。海外志向の新しい評価式は作らない。
- 明示オファーはproposalに`offeredDate`と`marketEntry`のコピーを保存。新提示はstate.dateと一致し、現市場と同じentry ID/内容を要求する。既存未記録のC-1/2D入力は候補側も市場情報未記録の場合にだけ同年度の旧経路で維持。`isFA`や表示用の理由文から区分を補完しない。
- 明示回答には解決履歴の`answeredDate`を保存。`proposal`は変更せず、同年度遅延受諾のみ既存`acceptedProposal`に実効力日を記録。オフ契約は同年オフで回答し、翌年2月1日効力、1–3年（育成1年）を全年度審査。国内外FAはオフのみ、releasedは開幕前/シーズン/オフ。期中は回答日から月割り。
- A/Bの他球団移籍は提示/留保まで可能だが受諾を拒否。補償の台帳/予算/人的移動が揃う後続まで安全に保留する。旧所属への残留、Cランク、外国人exempt、releasedは受諾可能。海外FAのNPB内契約も同じ制約。海外移籍は既存離脱経路を維持。
- `state.acquisitions?=[{proposalId,player,joinedDate?}]`はオフ受諾の加入履歴。playerはその時点の選手スナップショット、金額/球団/効力日は解決履歴と台帳から導出。受諾時に市場から除去し、将来signを台帳へ確定、現在名簿は変更しない。受諾済み案件は必ず加入待ち/加入済み履歴を1件持つ。受諾履歴と加入履歴を同時に失っても、未所属の将来獲得signから加入待ち情報の欠損を検出する。
- `join-fa {id,proposalId}`は効力年度の開幕前、2月1日以降に二軍へ一度だけ追加。加入日を記録し、効力日・年俸・満了は変更しない。加入待ち選手を市場/新人/他球団へ二重配置しない。加入待ちのままシーズンや次年度へ飛ばすstateを拒否する。加入後の履歴は元所属を現在所属として強制せず、その後のトレード/退団を妨げない。
- 現名簿＋受諾済み支配下新人＋加入待ち支配下獲得を70人に収める。育成は支配下枠と420万円維持費へ数えず、実額を留保/負担。新人joinと市場joinの順序で重複計上しない。未回答だけでは枠を確保せず、受諾で再審査。
- `reject-fa`で拒否、`cancel-fa`で球団取消、競合受諾でlost。留保を解放し原提示と回答日を維持。ID再適用はJSON後も一度だけ、別IDの二重受諾/加入は拒否。見積/失敗は全体非変更。
- 回答期限/自動失効は未導入。未回答はJSON後も維持し、春も勝手に受諾せず取消/拒否できる。明示履歴はenteredDate ≤ offeredDate ≤ answeredDate ≤ state.date、joinedDate ≤ state.dateを検証する。開始年度を越える予算更新の前に未回答を明示解決する。旧効力年度より後まで持ち越す不正stateは黙って補正しない。日付/phaseは呼出側の信頼済み暦でありstate全体の認証は対象外。

## 非対象と次工程

本番hook/CPU/委任/Worker、旧セーブ移行、全体年度更新、UI/コーチ/校正/実iPhone性能、新規乱数/評価式、代理人、回答期限自動処理、保証債務の精算方式変更は対象外。次は補償と海外離脱の共通取引設計、回答期限/年度移行adapter、本番の保存と人/CPU接続を依存順に進める。完全バックアップ/復元は保留。main直接push、マージ、自動マージは禁止。
