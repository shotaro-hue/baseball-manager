## 正本と順序

bootstrapTeams.createInitialTeamsの実名簿→保存teams(players/farm)・当年statsが選手入力、
engine.spending.ledgerが元契約/終了年、reservationsが正式留保の正本。
旧契約は移行せず、実名簿試験は既存annual fixtureと明示予算policyを使う。名簿給与を補正しない。
年度producerの必要順序は退職予約の確定→12/1 posting→成長/要求額・更改留保→FA→
当年成績保存→翌春加齢/成績リセット。予約中も希望候補から除外する。
既に留保・将来契約がある選手は#555の除外を維持し、取消で候補を増やさない。
全球団の希望を先に生成し、全CPU判断を次に固定し、最後に市場を実行する。
承認予定選手を以後の役割深度から除き、市場の成否によって球団判断を変えない。
12/1以外やannual必須入力不足をlegacy/空配列へ代替しない。

## 方針・代替

採用: native `advance-posting-phase` が既存generate/request/decide/run-marketと共通の
検証・全年度支出審査を使い、一revisionで候補を返す。同期/非同期は同じgeneratorを使い、UIでは球団・案件境界で既存yieldToBrowserへ制御を返す。共通barrierは準備開始から保持する。world取引を複数作ってrevisionを
書換える案、選手ごとの保存、旧即移籍処理は不採用。
実行単位全体が検証・保存に成功してから採用。失敗時は案件と理由を返し全体非変更。
親receiptに生成子参照、判断入力・理由・子署名、市場参照を保持する。
公開済み生成の再利用は許すが、新判断・市場子への親後付けは保存境界で拒否する。
再試行は同じ年度ID・root・用途streamを使う。履歴は現在能力から再計算しない。

## 最小CPU判断v1（ゲーム仮定）

既存tradeValue（年齢/能力/将来性）、sameRole、evaluateOrganizationNeedsの必要人数、
getFrontOfficePlanPublicの方針を使用。育成・退職予約者を代替戦力に数えない。
1. 同役割の残人数が既存必要人数未満なら拒否。
2. coreか価値70以上の複数年主力は、30歳以上の再建方針を除き拒否（既存tradeの70を再利用）。
3. 同役割代替の価値が本人以上なら承認。
4. 30歳以上で当年満了、または再建方針なら承認。それ以外は戦力維持で拒否。
新しい価格・希望確率・保証/予算免除は導入しない。30歳は既存のprime境界、
承認順は型付き選手IDの安定順。同等の主力を全員同時に放出しない保守的仮定。
現実球団の承認率を実証・校正した規則とは扱わない。
