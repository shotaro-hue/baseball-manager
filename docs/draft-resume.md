# ドラフトから新シーズンまでの保存・再開

編成計画の補強結果に続き、候補確認、1巡目と抽選、2巡目以降、結果レビュー、キャンプ、新シーズン案内を再開対象とする。画面上部に現在の工程、保存待ち／保存済み、途中保存を表示する。

候補・指名結果・スカウト開示・残ポイント・配分・表示切替を保存する。抽選はCPUの選択と当選結果を保存し、ロード時に引き直さない。進行タイマーは画面を離れると解除する。CPUの指名アニメーションは保存時点から続く。

自動保存は変更後750msで行う。保存前に終了した変更は復元できないので、画面を閉じる前は「途中保存」で完了を確認する。容量不足などの保存失敗は通知し、保存待ちのまま再試行できる。

ドラフトの所属更新は一度だけ適用し、キャンプの変動値も保存する。入団拒否した選手は獲得数・所属に含めない。未記録の当選球団を球団ID 0と解釈しない。候補は明示的な指名ボタンで選び、スマホでは候補とログを縦に並べる。既存の詳細と予算配分は維持する。

年度更新中は自動保存を止め、旧年度の状態で新年度セーブを上書きしない。年度成績の保存、次年度日程の準備、新年度セーブが成功してから年度と所属状態を更新する。失敗時は同じキャンプから再試行する。新年度案内をロードしても年度をもう一度進めない。

年度成績はID 0も保存する。オフシーズンFA移籍で既に旧所属の年度成績を保存した選手に、新所属で未出場の年度成績を追加しない。通常の選手の今季成績は保存してからリセットする。年齢・在籍年数・既存の契約残年更新を一度だけ実行する。表彰・優勝履歴は維持する。

既存セーブは従来のホームまたは編成計画から再開する。年度・球団が違う計画は適用しない。再開先の必須データが欠ける場合は補強結果など直前の工程へ戻す。

単体テストで抽選結果の復元、指名と所属の重複防止、キャンプ再開、保存失敗と再試行、年度成績と移籍の記録を検証する。スマホ実機での目視確認はユーザーが担当し、開発側では未実施。
