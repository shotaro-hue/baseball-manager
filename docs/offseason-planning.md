# シーズン終了後の編成計画

引退確認後に編成計画を開く。残留・交渉・放出候補の選択は方針だけを保存し、選手の所属や契約を変更しない。契約更改・FA補強を開始すると、自球団／補強市場／結果確認を切り替えながら判断できる。

## 判断に使う情報

- 所属人数と放出候補を除いた予定人数、ポジション別人数、補強ポイント。
- 来季年俸見込み、実際の残予算、未合意・対応待ち人数。
- FA宣言者、今季の成長と衰え、既存の選手詳細と比較への入口。
- 来季年俸見込みは未合意の提示額を含む。実際の残予算とは分けて表示する。FA契約は年俸×契約年数を契約時に支払い、通常の契約更改はその場では予算から引かない既存仕様を維持する。
- 未記録は「—」で表示し、実測の0と区別する。

## 確定操作

通常の契約提示も確認画面を経由する。契約、戦力外、減額制限超過による自由契約、交渉決裂によるFA宣言を実際の所属・履歴・市場に反映する。確定済みの契約を方針変更で取り消すことはできない。

FA宣言後も市場から宣言残留できる。当年度に契約した選手は再更改・戦力外の対象にしない。市場の重複契約、同じ放出の再処理を防ぐ。

「編成を確定」では未合意・対応待ちが残る場合に進行を止める。放出候補だけが残る場合は最終確認で放出し、その後にCPU補強を一度だけ実行する。各球団の補強結果を確認してからドラフトへ進む。

## 保存と再開

編成計画と補強結果を自動保存し、明示的な保存も可能。方針、提示額、契約年数、交渉回数とログ、選択中の選手、表示切替、市場の検索・絞り込み、契約結果、CPU補強結果を復元する。CPU更改・FA宣言・CPU補強をロード時にやり直さない。

補強結果からドラフトへ進む前にも保存する。ドラフト以降も途中保存と再開に対応する（[保存対象と年度更新](draft-resume.md)）。既存セーブは従来どおりホームから再開する。計画の年度・球団・形式が一致しない場合もホームへ戻る。

保存する画面用の選手スナップショットは数値成績に絞って容量を抑える。実際の選手・過去成績のデータは削除しない。

## 検証

追加テストは方針の可逆性、画面切替、契約確認、FA宣言残留、二重処理防止、予算不足、戦力外の参照整理、未合意による進行制限、CPU補強の一度だけの実行、保存復元を確認する。

スマホ実機の目視確認は未実施。ユーザー確認で長い選手名、人数の多い一覧、ダイアログからの復帰、狭い画面での固定ナビを確認する。
