# F-03: 通常進行と二軍実測記録の接続

F-01の簡易試合モデル、F-02の所属独立記録と保存基盤を、一軍の単日Worker・一括Worker・戦術試合へ接続する。既存保存形式・一軍成績・旧stats2は維持する。

## 進行と確定

- 試合前の一軍編成確定後、同じ12球団snapshotから二軍の当該roundを計算する。試合後の昇降格やトレードで当日の所属を遡って変更しない。
- `prepareFarmProgress`で記録候補を作り、一軍更新後に`finishFarmProgress`で当日の二軍所属者の負荷・休養を選手IDで反映する。昇格者にも当日の二軍負荷が残る。
- 故障・登録クールダウンは既存一軍ライフサイクルだけが一度減算する。故障残日数1は試合前に出場せず、試合後に回復する。二軍モデルでは新規故障・成長・収入・一軍通算を生成しない。
- Reactでは球団・年度・round・saveId・二軍記録を一つのreducer actionで採用する。WorkerのtaskIdと状態変更tokenで、編成変更・ロード・新規ゲーム後の古い回答を破棄する。戦術試合の重複完了判定には別のロードセッション番号を使い、同じsaveIdの巻き戻しロード後も再実行できる。
- 年末の旧`runFarmSeason`呼出しはすべて停止する。

## 負荷の初期値

球数を捏造せず、モデルが記録するBF・PAを使う。投手は`ceil(BF/2)`を5〜40で制限し、2連投で5、3連投以上で15を加算。投球日の直近7公式roundを保持する。野手はPAを1〜5で制限する。未出場投手は`round(8+(recovery-50)/10)`、未出場野手は6回復し、上限100とする。出場後conditionの下限は20。年度更新で登板日とlastPitchedをリセットする。長期バランス・性能評価はF-04で実施する。

## 新規・移行・保存

新規ゲームは初回保存から`source:new`を持つ。旧セーブはロード時に次の未実行公式roundから`source:migrated`を作り、過去試合を補完せず、旧stats2を由来付きで保持する。初回の通常保存で永続化する。

進行保存は一軍と二軍を同じ候補snapshotで保存する。保存失敗後も整合した未保存候補をメモリに保持し、再試行で試合を再シミュレーションしない。

年度更新は旧日程を持つstateと`{year,teams,nextSchedule}`を`advanceFarmYear`へ渡す。旧二軍年度archive・旧年度日程履歴・新年度日程を同じ候補として先に保存する。保存失敗時は旧年度を公開したままにする。公式通算の既存処理を維持し、二軍成績を加算しない。

## 最小閲覧と表彰

既存編成の二軍一覧（スマホでは二軍切替から直接閲覧）、選手詳細の今季成績に年度・記録開始位置・簡易モデル由来・実施／未実施数・実測成績を表示する。選手IDによる球団間合計のため昇格後も参照できる。実測0、分母不足の`—`、未記録を区別する。旧推定は年度不明として別表示し合算しない。

F-03以降の当年二軍表彰は旧stats2から選出しない。規定確定前はpendingとして全タイトルnullを保存し、過去保存済み表彰は書き換えない。一軍表彰を変更しない。二軍ランキング・年度切替UI・年間表彰・CPU捕手補強・育成との詳細連携はF-04以降。

## 検証

単日／一括／戦術の二軍記録・負荷一致、故障1日とクールダウンの単回更新、昇格後負荷保持、キャンセル・古い回答、保存失敗再試行、年度保存失敗と日程archive、旧表彰保護を自動テストする。360／390／1440pxの既存編成・選手詳細を実ブラウザで確認する。
