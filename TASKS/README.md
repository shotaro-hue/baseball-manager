# TASKS/

実装タスクの要件・受け入れ条件を保存する場所です。共通の開発ルールは [AGENTS.md](../AGENTS.md)、検証とPRの基本方針は [CONTRIBUTING.md](../CONTRIBUTING.md) を参照してください。

## 使い方

### 1. タスクを定義する

ユーザーの目的と最新のコード・関連PRを確認し、`TASKS/<name>.md` に目的、対象、非対象、受け入れ条件、検証方法を記載します。新しい仕様の判断が必要な場合は実装前に合意し、既に合意済みの内容は確認を繰り返しません。

### 2. タスクを指定して実装を依頼する

WorkやCodexへの依頼例:

```text
AGENTS.mdとTASKS/<name>.mdを読んで対応してください。
最新mainと関連PRを確認し、既に実装済みの部分は再実装しないでください。
対象範囲の変更・検証を行い、baseがmainのPRを作成してください。
mainへの直接push・自動マージはしないでください。
検証結果と未検証事項を報告してください。
```

## 過去のタスクを読む場合

既存のタスクには作成当時の構成・ブランチ名・コマンド・進捗が含まれます。ファイルが残っていることやチェック欄が未更新であることを理由に、未実装と判断しないでください。現行の `AGENTS.md`、`package.json`、`.github/workflows/ci.yml` と関連コード・PRを確認してから利用してください。

## ファイル命名規則

`<機能名の kebab-case>.md`。例: `farm-simulation.md`、`allstar-game.md`、`waiver-system.md`。

## 実装済みタスクの扱い

実装状況とPRを記録して保存できます。削除・アーカイブは別の整理作業として明示的に行い、無関係なタスクを今回の変更に巻き込まないでください。
